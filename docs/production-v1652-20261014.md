# Production v1652 — omit history entries without user-visible changes

Published 2026-10-14 Moscow time at https://vniipo-help.ru/bike-packing/.
Source commit: `3817af08864536ed32bac622687029c32040148c`.

History pages now inspect their saved before/after snapshots before rendering
and omit confirmed entries without user-visible changes. Counts and the latest
Undo action refer to the visible actions. Technical-only pages automatically
advance to older history, preserving server pagination cursors. Meaningful
daily checkpoints and explicit template deletion events remain available.
No database history rows, snapshots or account content are deleted.

Detail reads run with at most three concurrent requests and are cached for the
open dialog. Failed or incomplete inspections retain their original summaries
for retry instead of being treated as empty. Opening a subsequently verified
empty entry removes it from the list. Generation guards stop obsolete source
loads from replacing a newer view or repopulating its detail cache. Daily
checkpoint captions remain distinct from action captions.

This frontend-only approach adds detail requests to each loaded summary page.
It deliberately uses the same comparison as the detail view; server summaries
alone still do not account for the historical pouch migration. No API or shared
service was changed.
