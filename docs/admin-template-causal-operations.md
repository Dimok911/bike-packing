# Причинные операции шаблонов: административный режим

Дополнение к этапам 07 и 11 от 2026-09-06 по уточнению пользователя.
Редактирование и запись шаблонов доступны только администратору. Этот перечень
не расширяет права обычного пользователя, не меняет Shared Auth, не разрешает
deployment и не означает, что личный DB-only outbox уже покрывает шаблоны.
Существующее чтение опубликованного шаблона/создание личной копии не превращаем
в право изменить источник. Содержимое каталога производителей не меняем.

## Перечень направлений

Каждый пункт требует отдельной проверки формы, сохранённого действия, серверного
подтверждения и файлового пакета. Все пункты пока открыты.

- [ ] Сумка из шаблона в выбранную целевую укладку/шаблон: целое дерево и только
  оболочка без содержимого — разные сохранённые планы копирования.
- [ ] Сумка из личной укладки в изменяемый шаблон: новые ID в namespace цели,
  явное происхождение, права администратора на целевой шаблон.
- [ ] Вещь/ячейка и вложенный контейнер из шаблона, в шаблон, внутри одного
  шаблона и между двумя шаблонами; целевая сумка, позиция и количество фиксируются.
- [ ] Несколько выбранных вещей/сумок: состав пакета и новые ID сохраняются один
  раз; подтверждённая часть не копируется заново после сбоя другой части.
- [ ] «Связать существующее», «независимая копия» и «добавить недостающее»:
  результат выбора не пересчитывается по изменившемуся источнику при повторе.
- [ ] Копия целого шаблона, включая язык, справочники, размещения и фотографии;
  новый административный черновик не выдаётся за опубликованный шаблон.
- [ ] Прямые правки, удаление, порядок, сохранение черновика, публикация данных
  и снятие публикации; старое подтверждение не восстанавливает удалённое.

## Найденные точки входа

| Область | Точки входа |
| --- | --- |
| Отдельная вещь и целевая ячейка | `copyItemToContainerInLayout`, `duplicateItemToContainerInLayout` в `src/app/app-tail-controllers.js` |
| Сумка/дерево и выбор способа копирования | `copyContainerTreeToLayout`, `duplicateContainerSnapshotToLayout`, `linkExistingContainerTreeToLayout` там же |
| Массовое копирование | `copyCatalogItems`, `copyCatalogRootContainers` там же |
| Копия шаблона и административный черновик | `loadPublishedTemplateCopySource`, `createTemplateCopyFromSource`, `createTemplateCopyDraft` там же |
| Сохранение административных изменений | `saveLayoutMutation`, `scheduleActivePublishedEditSave`, `flushActivePublishedEditSave` и административная ветка `saveState` |
| Фото копий | `copyRecordPhotosForLocalDuplicate`, `markLayoutPhotosForCurrentListCopy`; нужен отдельный устойчивый файловый план |

## Обязательные гарантии

1. Источник: ID шаблона/списка, revision либо действие-предшественник, точный
   снимок и версии фото. Если администратор только что изменил шаблон, копирование
   не должно незаметно использовать его более старую опубликованную версию.
2. Назначение: административный namespace, ID цели и её исходная revision,
   сохранённые новые ID, положение в дереве и порядок элементов.
3. Сервер проверяет чтение источника и право записи в целевой шаблон атомарно
   с проверкой версий, изменением данных и квитанцией. Отсутствующая зависимость
   ожидается либо даёт явный конфликт, но не успешную устаревшую копию.
4. `изменить A → скопировать A в B → удалить A`: копия использует новую версию A,
   удаление учитывает зависимое чтение, все перестановки доставки дают тот же
   допустимый результат. UUID — идентичность, а не порядок и не время.
5. Обрыв связи, reload, другой маршрут, частичный файловый пакет, смена аккаунта
   или выход из админского режима не создают новый пакет и не применяют старый ACK.
6. Публикация данных внутри приложения подтверждается только после обязательных
   записей и файлов. Публикация сайта/сервисов — отдельное разрешение пользователя.

До реализации этих адаптеров этап 11 не закрывается. Нельзя просто пропустить
административный запрос через личную очередь или включить общий release-флаг.
