# Сумка с фото из окна копирования вещи

Локальный этап после FE aab9868 / API a1ef555, без публикации и включения
флагов. В пустой выбранной укладке можно создать сумку с фотографиями,
сохранить её составной формой и вернуться к исходному выбору места вещи.
Выбранная укладка фиксируется целиком до подготовки записи. При нехватке
места форма остаётся открытой, а выгрузка содержит сумку, размещение и фото.

Возврат к выбору использует существующий обработчик закрытия формы; закрытие
происходит только после записи полного действия. Потеря ответа о файле или
сумке восстанавливает исходные записи и файлы без повторной загрузки.
После перезагрузки сам выбор места открывается заново пользователем.

Связывание вещи с подтверждённой сумкой использует существующий `link-item`
через очередь до изменения интерфейса. Для этого компилятор размещения
разрешает `link-item` в другой укладке, сохраняя активную укладку, её
упаковку и исходные фото. Новая связь получает количество 1 без упаковки.
Номер подтверждённой версии сумки становится базовой версией следующего
действия. Другие операции сохраняют требование активной укладки.

На этапе e6f2fee, пока сумка с фото не подтверждена, следующий выбор места останавливается
до записи и изменения интерфейса; окно выбора и исходная очередь сохраняются.
Постановка такого следующего действия в зависимую очередь ещё открыта и
требует адаптера потомков обычной фотоформы. Это не закрывает весь раздел.

Следующий локальный адаптер описан в `personal-pending-photo-form-updates.md`:
с его отдельным флагом выбор сохраняется как зависимое действие до подтверждения
сумки. При выключенном флаге остаётся указанное выше прежнее ограничение.

Проверены 34 focused, 596 transport, 896 critical. Первые UI после подключения
формы: 10/10 Chromium/mobile WebKit, 2,4 мин (container-copy-target-ui-5.log).
После перевода связывания на сохранение до отображения расширенный UI:
30/30, 6,9 мин, Chromium/mobile WebKit (container-copy-target-ui-6.log),
с прежним копированием вещи и проверкой неподтверждённой цели. FE check прошёл.
API/MySQL дополнен действительным frontend `link-item` после фотоформы:
потеря подтверждения, перезапуск, точное чтение результата, сохранение
исходной укладки и фото, затем удаление списка и позднее старое сохранение.
Полный API/MySQL: 218/218, 250,47 с (container-copy-target-mysql-1.log).
Все процессы завершились exit 0, временный MySQL остановлен.

Первые тестовые ошибки исправляли сценарий, а не защиту данных: UI1 искал
кнопку создания в заполненной укладке, UI2/3 использовали старую пустую
укладку без версии миграции количества. Защита остановила её скрытое
изменение до отправки. UI4 ожидал отдельный признак размещения у прежнего
общего сохранения; дальнейший перевод этого пути на `link-item` выполнен
отдельно и проверяется расширенным набором. Продолжение общего списка
обязательно: ожидающие формы, каталоги, обмен, администрирование и аудит.
