# Восстановление незавершённой подготовки публичной копии

Локальное продолжение раздела 07, 2026-09-09. Публикации и включения рабочих
флагов нет. Поддерживаются целая укладка v1 и отдельные записи v2.

Раньше запуск приложения искал подготовленное действие с файлами. Если сбой
произошёл после сохранения выбора, но до создания действия, выбор оставался
в журнале без окна восстановления. Следующее сохранение могло обойти его.
Теперь любой незавершённый выбор текущего пользователя/списка удерживает
редактор до явного решения. Связанные с очередью записи и точные терминальные
подтверждения повторно не предлагаются.

Продолжение использует прежние источник, язык, числовую версию, состав копии,
место назначения и все ID. Полный публичный payload не запрашивается заново.
Если действие и его native-файлы сохранены, связывается именно это действие
без скачивания файлов. Если native-запись ещё не создана, читаются исходные
URL из сохранённого выбора; подготовленное действие должно совпасть целиком.
Изменившиеся байты не заменяют ранее зафиксированный файл. Недоступный файл
оставляет выбор и действие для восстановления/экспорта, без частичной копии.

Первый ещё не сформированный результат проверяется обычным серверным
контрактом: публичная доступность, исходная версия, файлы, права на личную цель,
её версия и одна атомарная квитанция. Восстановление не подтверждает успех
локально и не принимает новую версию личного списка за исходную.

Журнал сравнивает полное проверенное содержание действия, независимо от
порядка JSON-полей. Первоначальная сериализованная запись сохраняется без
перезаписи. Смена контекста, иная подтверждённая цель, чужая/повреждённая запись
или несколько незавершённых выборов останавливают продолжение. Порядок между
несколькими выборами не выводится из UUID или времени; отдельный UI выбора
и отказа от таких подготовок остаётся открытой частью.

После нехватки места окно обновляет доступность продолжения по новому читателю
журнала. Уже установленная блокировка редактора сохраняется; восстановление
не снимает её до проверки квитанции и явного обновления страницы.
Чтение и экспорт доступны с выключенными writers; возобновление v2 требует
собственного флага отдельных публичных записей.

Проверки текущего среза:

- 17 новых модульных сценариев, 696/696 transport, 896/896 critical,
  проверка исходников и сборка frontend.
- 40/40 целевых API/MySQL, включая 8 новых случаев: выбор без действия,
  действие без native-файлов, native без очереди, вариант без фото; v1/v2.
  Изменённые байты отвергаются, исходная запись после отказа сохраняется.
  Затем проверяются lost ACK, перезапуск, SQL-откат, удаление источника/цели
  и точный повтор квитанции. Backend-тесты закреплены в `54be06c`.
- 16/16 UI для v1/v2 на Chromium и мобильном WebKit: отказ чтения файла,
  отказ журнала действия без фото, отказ native и отказ связи с очередью.
  Проверены доступность продолжения сразу после ошибки, холодное восстановление,
  сохранение всех ID и отсутствие второй копии/загрузки после перезагрузки.
- Ещё 6/6 и 8/8 UI: четыре проверки запрета старых путей при выключенном
  флаге, четыре проверки сохранённого выбора/экспорта с выключенными v1/v2,
  шесть проверок обычной фотоформы при нехватке места и повреждённой связи.
