# Административная копия после личного сохранения

11.09.2026. Продолжение FE `e722b4d7`, BE `9ba6b37` без изменений для этого среза.
Публикации нет; флаги исходников OFF. Проверяется подтверждённый личный источник
при включённой личной очереди, а не завершённое подключение ожидающего источника.

## Две воспроизведённые ошибки

Подготовка личного источника копии читала сервер через общий `apiFetch` с POST.
Защита личной очереди принимала этот запрос за прямую запись и блокировала его.
Чтение перенесено в административный клиент с существующими проверками аккаунта,
прав, текущего контекста и ухода со страницы. Журнал записи при подготовке не
создаётся; общий запрет обхода личной очереди не ослаблен.

После этого копия успешно сохранялась, но перезагрузка подставляла устаревший
административный редактор из локального снимка личного журнала. В обычном случае
терялось отображение уже принятой версии; при нехватке места в административном
журнале — выбранный план, который успел сохраниться в общем зеркале. Обе ошибки
воспроизведены настоящей формой копирования.

`recoverPersonalAdminDrafts` при восстановлении личного журнала берёт отдельные
административные записи из текущего зеркала того же аккаунта. Личные записи,
словарные значения, выбор укладки и отметки упаковки остаются из личного журнала.
Восстанавливаются также каталожные вещи без размещения; отсутствующие в зеркале
административные записи не возвращаются из старого личного снимка.

Перед объединением проверяются binding/namespace, коллизии ID и принадлежность
всех связей дерева. Доказуемое уменьшение подтверждённой версии, повреждённое
зеркало или ссылка на личную запись останавливают восстановление, сохраняя оба
исходника. Это не новая политика разрешения несравнимых планов разных вкладок:
проверка сохранённой цепочки административных действий остаётся обязательной.

## Проверка

Исходные неуспешные прогоны сохранены: `resume-private-admin-recovery-ui-1.txt`
(2 failed / 2 not run, остановка на подготовке) и `...ui-2.txt` (2 failed / 2 not run,
остановка после reload). Трассы второго прогона сохранены отдельно.

После исправления: Chromium 4/4; затем Chromium/mobile WebKit 12/12. Последний
контроль после замечаний независимого review: **12/12**, 2,8 минуты, без повторов
и пропусков (`...ui-5.txt`).
В целевом наборе 8 новых сценариев: demo/shared × подтверждённая копия/квота
записи плана × два браузера, плюс 4 прежних проверки обратного импорта. Сверяются
точный результат и исходные ID, один административный POST, один личный POST,
неизменность личного серверного содержимого и отсутствие ошибок страницы.

Проверки очереди после окончательных защит: 1293/1293, включая 7 проверок
восстановления namespace и 25 проверок административного клиента. Проверка
исходников завершилась с exit 0 (`...source-2.txt`). Backend API для неизменённого контракта не
перезапускался; прежние 475/475 относятся к `9ba6b37`.

UI-сборка использует текущее рабочее дерево, в том числе отдельные изменения
галереи. Этот прогон не объявляется проверкой галереи на точном опубликованном
коммите. Полная приёмка WebKit и всего перехода остаётся открытой.
