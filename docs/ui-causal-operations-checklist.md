Промежуточная реализация 2026-09-06:

- `personal-save-outbox.js`: снимок + действие одной синхронной записью до
  локального зеркала; отдельные неизменяемые ключи, зависимости без часов,
  сохранение обеих ветвей при гонке вкладок и остановка на конфликте/повреждении.
- В `app.js` подключены gated persistence/load/save/manual-sync hooks для уже
  известного личного списка. Незавершённый журнал восстанавливается раньше
  обычного локального зеркала; старые прямые записи и загрузки фото блокируются.
- Отправка предшественников получает только историческое подтверждение,
  не применяет их данные к интерфейсу. Последнее действие проходит проверку
  текущей серверной версии, аккаунта/локального поколения и локальный checkpoint.
- Явный UUID теперь распознаётся после смены поколения редактора; тот же UUID
  с другими данными блокируется. Неизвестный результат не разрешает новый POST.
- `PERSONAL_SAVE_OUTBOX_ENABLED = false`; остальные release gates также false.
  Это НЕ завершение пункта: первичное создание через реальный UI, восстановление/
  конфликты с новой серверной базой, файлы, полная пользовательская проверка и
  политика хранения больших журналов ещё требуют адаптеров и тестов. Список
  с фото в пилоте останавливается, а не отправляет незавершённый составной пакет.
- Модуль/обёртки проверены unit-тестами, браузерный стенд очереди — Chromium и
  mobile WebKit (14 сценариев). Стенд не заменяет полный проход реальных кнопок.

- Потеря локального указателя восстанавливается из действия; пустой/ошибочный

- Проверено: `test:transport` 80/80, `test:critical` 877/877, `check`, сборка;
  стенд очереди Chromium + mobile WebKit 18/18, включая создание → lost ACK →

  Итоговый совместный повтор transport + queue после всех правок: 44/44.
- Первое локальное изменение после подтверждённого пустого ответа о списках тоже

- Запоздавшие ответы списка, его подробностей и инкрементальных изменений

  Файлы остаются отдельным этапом; никаких флагов, миграций и публикаций не было.

Уточнение пользователя о двух маршрутах: требуется автоматический начальный
выбор RU → EU при транспортной недоступности RU. Реализован выключенный
начальный автовыбор, отдельный пункт верхнего меню и настройки «Маршрут API»:
автоматически / российский /
европейский. Ручной выбор важнее автоматического; применяется после обновления
вкладки. После выбора маршрут закреплён, автоповторов бизнес-запросов нет.
`AUTO_TRANSPORT_RELEASE_ENABLED` и `EU_TRANSPORT_RELEASE_ENABLED` остаются false.
Это одна база через два адреса, не две независимые базы. 401/403,
бизнес-конфликт, неверная идентичность API и неизвестный результат уже отправленной
записи не разрешают слепое переключение/повтор. Перед повтором нужна точная
квитанция того же действия. Переключение не меняет operation ID/данные/зависимости.

Текущий срез 2026-09-06 — журнал, реальные формы и удаления:

- В журнале одна полная бизнес-копия: локальные отличия снимка хранятся патчем.
  После подтверждения цепочка заменяется проверенной опорной записью; перед
  удалением старых ключей атомарно сохраняется точный перечень очистки. Сбой
  на каждом шаге очистки, quota и поздняя ветвь другой вкладки проверены.
  Неподтверждённые действия не очищаются. Срок хранения серверных квитанций и
  окончательная политика локальных коротких подтверждений остаются открытыми.
- Более новая серверная база принимается только после подтверждения локальной
  вершины. Старые UUID/данные не переписываются; следующее действие использует
  новую проверенную revision. Неподтверждённый конфликт не перебазируется сам.
- Намеренное удаление вещи/сумки фиксируется в том же неизменяемом действии.
  Проверка потери данных учитывает только это удаление и его ссылки, но не
  разрешает исчезновение остальных сущностей/размещений. Удаление последних
  вещей/сумок больше не блокируется как случайно опустевший список.
- Восстановление берёт бизнес-данные из журнала, в том числе подтверждённый
  пустой список. Из обычного зеркала разрешены только настройки отображения,
  не сущности и не отметки упаковки.
- Полный изолированный UI: 8/8 Chromium + mobile WebKit. Настоящие формы
  первичного создания укладки/списка, сумки и вещи; lost ACK → reload без
  повторного POST; вложенная сумка, редактирование, окончательное удаление и
  очистка размещений; более новая серверная база и последующее изменение.
  API этих UI-проверок — контролируемая имитация, не live-публикация.
- Локально: `check`, 877/877 critical, 89/89 transport; транспорт + очередь
  Chromium/mobile WebKit 44/44. Добавлен отдельный paired MySQL-сценарий для
  реального API: create/update/delete-снимок → lost ACK → compact → reload →
  новая серверная база. Результат нового совместного CI фиксируется отдельно.
- Пилот включается только преобразованием тестового bundle в игнорируемом
  `test-results/personal-ui-build`. Все source release gates остаются
  false; обычная сборка не использует тестовое включение.

Этап 01 ещё не означает готовность остальных этапов. Открыты явное разрешение

## Когда отмечаем пункт выполненным

Одновременно выполнены: подключены реальные действия интерфейса, сохранены
данные и зависимости до отправки, есть соответствующий серверный обработчик,
пройдены проверки перезагрузки/повтора/потери ответа/перестановки запросов и
смены аккаунта. Для составных действий дополнительно проверены частичный пакет
и точная версия источника. Фиксируем изменённые файлы, пару frontend/backend
коммитов и результаты тестов. «Проверен отдельный модуль» не закрывает пункт UI.

Изменения темы, открытие модалок и другие действия без записи бизнес-данных
не превращаем автоматически в серверные операции. Каталог, Shared Auth, proxy
и deployment остаются вне этого списка реализации до отдельного разрешения.
