# Массовая копия личных записей с фотографиями

Локальное продолжение 2026-09-08. Публикация отложена пользователем.
Проверенный backend: `6a81211`.
Новый `PERSONAL_PHOTO_COPY_BATCH_ENABLED = false`; серверная возможность
`personalCausalPhotoCopyBatchV1` требует отдельного выключенного флага
`BIKE_PACKING_CAUSAL_PHOTO_COPY_BATCH_ENABLED` и всех прежних photo/copy gates.

## Единый выбранный набор

Массовая кнопка каталога фиксирует один `photos.mutate`, `action: copy-batch`.
`owners` содержит полные источники, числовые версии и новые ID всех выбранных
вещей либо корневых сумок. `changes` содержит полный упорядоченный набор
копируемых фотографий с отдельными новыми photoId/assetId. Записи без фото
входят в тот же пакет; их нельзя пропустить как необязательные. Максимум —
50 владельцев и 50 фотографий, с прежним ограничением размера всего запроса.

Подготовка до окна подтверждения синхронно сохраняет источники, метаданные
и все ID. После согласия SELECT-only чтения сверяют каждый источник с этим
выбором и общей базовой версией. Изменение последней карточки останавливает
весь пакет. Повтор submit сохраняет исходный promise и ID даже после ошибки.
Quota сохраняет полный кандидат для восстановления, не применяя часть копий.
Снимок и действие записываются вместе до изменения экрана.

Сервер проверяет все источники и отсутствие целей до публикации владельцев.
Проверенная копия запроса сохраняется до первого ожидания SQL. Каждый владелец
сохраняет все поля источника, кроме нового ID, имени/метаданных копии и
размещения. Все новые владельцы, фото, производные assets, история и результат
подтверждаются одной бизнес-транзакцией. Ошибка последнего фото откатывает
первые фото и владельцев. Физические неизменяемые файлы используются повторно.

Обычная одиночная форма по-прежнему запрещает пустой список фотоизменений.
Только внутренний компилятор массового пакета разрешает владельца без фото;
HTTP-параметр не может включить это исключение. Прочие batch-правила не меняются.

## Подтверждение и восстановление

`photoCopyBatch` в квитанции перечисляет всех созданных владельцев. Клиент
проверяет этот список, все поля владельцев, точные фото/asset ID, порядок и
метаданные. Частичная успешная квитанция не закрывает действие. При reload
читатель распознаёт пакет и с выключенными writer gates. Потерянный ответ
восстанавливается по прежнему ID; исторические данные не заменяют текущий
серверный список. Отмена целого пакета и последующий выбор актуальной версии
сервера остаются двумя разными решениями. Файлы повторно не загружаются.

## Оставшиеся границы

Этот участок — выбранные объекты одного личного каталога вне укладки.
Деревья, помещения копии в укладку, целые укладки, другие списки, публичные
источники, архивы и административные операции требуют продолжения.
Удаление до подтверждения массовой копии пока заблокировано; одиночная копия
уже имеет отдельный проверенный путь. Локальное редактирование источника перед
ещё не подтверждённой копией также остаётся открытым сценарием.

## Проверки

Модули: 449 transport, 895 critical, 53 серверных operation и 74 source/service
прошли. Новые unit-тесты проверяют смешанный набор, отсутствующий `photos`,
полную неизменность, отказ последнего источника, quota, gates и ложную частичную
квитанцию. **20/20 UI Chromium/mobile WebKit** прошли без повторов за 6,0 минуты
(`copy-batch-ui-1.log`). **129/129 API/MySQL**, 80,71 с, без skips
(`copy-batch-mysql-4.log`): откат на последнем источнике/фото, ожидание неизвестной
зависимости, lost ACK/restart/GET, удаление источника до восстановления квитанции,
неизменность физических путей, отмена с потерей ответа, отложенный выбор и
отдельное keep-server. Все процессы завершены. Итоги Trello не обновлялись:
последний установленный сбой доступа остаётся в отдельном журнале продолжения.

Обнаружено и исправлено: отсутствующий цвет сумки в общем помощнике становился
`undefined`; точная исходная форма поля теперь сохраняется. Отмена массового
пакета первоначально вызывала валидатор одиночной формы; теперь выбирается
собственный валидатор перед созданием записи отмены. Первый API-прогон выявил
ошибочную фиксированную версию второго тестового владельца; тест получает
реальную числовую версию. Третий прогон прервался при аварийном завершении Node
с кодом 3221226505 до новых сценариев; успешной проверкой он не считается.
