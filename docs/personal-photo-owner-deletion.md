# Удаление владельцев подтверждённых фото — локальный этап 2026-09-08

Обычные и массовые удаления вещей/сумок используют подготовленный снимок и
`list.update` с явным `userDeletion`. UUID назначается перед подготовкой;
снимок и намерение записываются до изменения живого состояния. Ошибка хранилища
оставляет исходного владельца на экране и в локальном зеркале. Последующее
обновление интерфейса не регистрирует второе действие.

Новый `PERSONAL_PHOTO_OWNER_DELETION_ENABLED = false` разрешает этот путь только
вместе с полным набором фотоформ. До сокращения владельцев проверяется весь
исходный набор ссылок: pending, legacy, чужой список и неполные данные не
превращаются в допустимое удаление. После сокращения фото всех оставшихся
вещей и повторно используемых вложенных сумок должны совпадать точно.
Каждый шаг активной причинной цепочки проверяется отдельно.

На сервере подтверждённое удаление последней сумки с фото допускается только
под проверкой версии и включённым photo publication. Postflight той же
транзакции отмечает удалённые ссылки и строки фотографий; физические файлы
не удаляются. Обычный SAVE не может убрать фото оставшегося владельца.
Удаление отдельного фото требует точного photo action с ID владельца/фото,
asset ID и исходной числовой версией. Параметр запроса не включает исключение.
