## Поведение

После копирования списка по новой или прежней общей ссылке можно сохранить
следующие формы, пока исходная копия ещё ожидает подтверждения:

- Фото, поля и размещение существующих вещей и сумок.
- Новую вещь или сумку сразу с фото либо сначала без фото.
- Следующее редактирование, порядок фото, замену и удаление.
- Отмену всей связанной цепочки и восстановление после перезагрузки.

После сохранения копии на устройстве адрес страницы переключается с общей
ссылки на личный список. Обычная перезагрузка продолжает работу с личной
очередью и не открывает заново исходный общий список.

У каждой формы остаётся собственное неизменяемое действие. Зависимости содержат
исходную серверную копию и непосредственного предшественника. Полный состав
ожидающих фото сохраняется для всех владельцев, включая владельцев из прежних
форм. Клиент не перечитывает изменившийся источник вместо сохранённой копии.

## Формат и ограничения

- Корень: существующий serverImport v1/v2. Формы: ownerResult v6 для
  существующего владельца и v7 для нового. Следующие изменения: photoResults
  v13/v14; до первой фотоформы используется существующая v12.
- Собственные serverOperationId и serverPhotoForm на диске и в запросах.
  Общая проверка состава фото повторно использует чистые функции валидации;
  публичное, гостевое или архивное происхождение в журнал не подставляется.
- Сервер проверяет актёра, список, версии, квитанции предшественников, точный
  состав файлов, существование владельцев и записи об удалении. Фото, поля,
  размещение и подтверждение фиксируются одной транзакцией.
- Отдельные клиентские и серверные флаги для фотоформ и создания владельцев.
  Все исходные флаги выключены. Отсутствие собственного разрешённого режима
  останавливает запись, отправку файлов и отмену до побочных действий.
- Выключение создания владельцев останавливает всю незавершённую цепочку,
  даже если последняя форма редактирует уже существующую сумку.
- Подтверждение не удаляет сохранённые исходники. Общая политика хранения,
  административные шаблоны и полный аудит всех точек входа остаются отдельными
  незавершёнными пунктами основного списка.

## Проверки на текущем рабочем дереве

Проверенные точки входа серверной копии:

| Путь | Подключение |
| --- | --- |
| Общий список / укладка | copySharedLayoutFlow → runCausalPublicLayoutCopy → типизированный serverImport |
| Вещь, оболочка сумки или дерево через выбор назначения | preparePersonalPublicPickerSource → runCausalPublicEntityCopy |
| Вещь из окна свойств в личный каталог | runCausalPublicEntityCopy с catalog=true |
| Следующая форма, новая вещь/сумка | собственная серверная цепочка, сохранённые исходники и формы ownerResult v6/v7 |
| Перезагрузка, отмена, проверка результата | общие окна восстановления читают собственную серверную цепочку и её квитанции |

Имена общих UI-функций содержат Public, но сохранённый запрос серверного
источника содержит только собственный serverImport. Это проверяется на новых
и прежних ссылках. Исходный серверный импорт не проходит через публичный
или архивный fallback.
