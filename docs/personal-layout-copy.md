# Создание и копирование целой личной укладки

Локальный участок после FE `7cdbc2d`, paired API `07f6502`, 2026-09-08.
Участок принят локально. Публикация отложена пользователем.

- `personal-layout-copy.js` готовит пустую укладку и копию личной укладки одним
  синхронным путём. До первого await фиксируются весь снимок, выбранная укладка,
  новое имя и новый UUID. Обычная копия укладки сохраняет размещения прежних
  владельцев, количества, порядок и packed; новые владельцы/файлы не создаются.
- Проверяются все связи выбранного дерева, состав, циклы, количество, namespace
  и неизменность структуры после обычной нормализации. Источник не ремонтируется.
  Формирование новой записи и словарей сохраняет обычную политику приложения.
  Полный исходный layout остаётся в frozen snapshot, включая неизвестные поля.
- Фотографии требуют полного подтверждённого личного inventory. Отдельный
  `PERSONAL_PHOTO_LAYOUT_COPY_ENABLED = false`; новый API capability не нужен,
  это прежний DB-only list.update с сохранением исходных фото.
- `preparePersonalLayoutCopyAction` подключён к обычному saveNewLayout до его
  первого await. Одна durable запись предшествует активной укладке/настройкам
  отображения. При quota полный кандидат остаётся в recovery, видимый список
  сохраняет прежнюю укладку. Повтор одного callback не создаёт другой ID.
- `userLayoutCopy` фиксирует источник/цель. Reconciliation снимает этот marker
  и прежний `userContainerTree`: новое решение не исполняет старое копирование.
- 476 transport, 895 critical, 74 source/service и source checks прошли.
  Из новых unit-тестов: полная копия
  с/без фото, пустая укладка, повреждённые источники, настоящий adapter/durable
  порядок/quota/смена редактора и отсутствие старых marker при reconciliation.
- 151/151 API/MySQL без skips, 159,52 с (`layout-copy-mysql-1.log`), включая
  4 paired сценария edit → layout-copy → source-layout
  deletion с reverse delivery, lost ACK/restart и поздним replay. API timeout
  расширен с 180 до 240 секунд: предыдущие 147 сценариев уже занимали 154 секунды.
  UI: 24/24 Chromium/mobile WebKit, 4,4 минуты с первой попытки
  (`layout-copy-ui-1.log`): 16 новых случаев, плюс прежние проверки
  удаления укладки и использования пустой укладки как цели следующего копирования,
  Все процессы API/UI завершены.
