## Problem and correction

The user reported a green indicator and “personal layouts loaded: 9 of 9” on
iPhone while only Local history remained available. v1653 retired the local
journal after successful writes, but ordinary server loads and unchanged-revision
checks did not reconcile it. Its account-activation comparison also compared
raw local UI state with a sync baseline, allowing already-saved entries to remain.
The phone itself was not remotely inspected; this matching failure path was
reproduced with an isolated browser fixture containing an older journal.

Confirmed full server loads now reconcile the journal, including the branch
where local and server states already match. Comparisons use the application's
sync representation to exclude local-only drafts and runtime placement fields.
Only the confirmed prefix is retired; later local actions remain. Reconciliation
is skipped while local photographs still await upload, because sync serialization
omits such photographs and would otherwise falsely appear equal.

Cached startup and unchanged-revision polling verify any remaining journal via
a read-only server snapshot request. That request never applies/replaces the
current state or initiates a save. Account/list guards prevent stale responses
from confirming another scope. Read failures preserve the journal. Cached startup
updates its baseline before awaiting verification so edits made during that wait
are not marked clean afterward. No journal is cleared merely on account activation
or because the connection indicator is green.
