# Добавить существующую сумку в административную укладку

11.09.2026. Backend `e7ac18c`, локальный коммит без отправки ветки.
Продолжение раздела 11. При выборе места для сумки из каталога
того же подтверждённого demo/shared доступна кнопка «Добавить существующую».
Она размещает полное дерево либо действительно пустую сумку с прежними ID.
Независимая копия остаётся отдельным выбором. Оба результата подготовлены
до окна подтверждения; выбранный результат сохраняется одним `template.save`.

Состав каталога не дублируется. Количество переносится в размещение, каталог
нормализуется по прежним правилам. Новые отметки упаковки не добавляются.
Любое пересечение уже размещённых ID запрещает связь; пустая оболочка не
может стереть состав непустой каталожной сумки. Отдельный режим «Только
недостающие» ещё не подключён.

API-проверка выявила потерю связей неразмещённого каталожного дерева: общие
серверные преобразования отделяли их от записей, но ни одна укладка их не
содержала. Исправление сохраняет эти поля в текущих строках только для
канонических административных demo/shared namespaces и соответствующего
source type. При чтении размещённые элементы по-прежнему берутся из
arrangement, неразмещённые — из текущих строк каталога. Пустая укладка не
заполняется автоматически из каталога. Личные списки сохраняют прежний формат.

Старый полный снимок не служит источником восстановления удалённых строк.
Ранее потерянные неоднозначные связи автоматически не достраиваются:
их сверка относится к открытому разделу старых данных.
