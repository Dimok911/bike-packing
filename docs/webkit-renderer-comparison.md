# Короткая проверка двух вариантов WebKit в Linux

11.09.2026. Дополнение к `browser-ci-diagnostics-2026-09-10.md`.

В ручном запуске `Frontend quality` появился параметр `webkit_diagnostic`.
Он выбирает два отдельных Linux runner: headless WPE и GTK под Xvfb. Выбор
движка подтверждён [launcher Playwright v1.62.1](https://raw.githubusercontent.com/microsoft/playwright/v1.62.1/browser_patches/webkit/pw_run.sh):
аргумент `--headless` выбирает WPE, запуск без него — GTK.

Оба runner выполняют одни и те же четыре существующих сценария составной
фотоформы: создание, перемещение, количество и удаление размещения, по пять
повторов. Используется обычный мобильный проект и исходные проверки результата,
один worker, ноль повторных попыток после ошибки, остановка после трёх отказов.
Собирается только нужный вариант приложения `photo-edit`. Ограничение job —
45 минут с установкой зависимостей.

В артефакты входят отчёт, первые отказы/трассы, сведения о жизни страницы и
метрики Linux/ядра. Обычный запуск quality сохраняет прежний полный набор;
диагностический параметр по умолчанию выключен. Текст прежних шагов сверен
побайтно после удаления добавленного условия, shell проверен `bash -n`.

Этот опыт проверяет связь сбоя с вариантом WebKit и средой. Успех короткого
набора сам по себе не устраняет нативный дефект и не закрывает приёмку.
Публикация, release-флаги и обработчики приложения этим параметром не меняются.
