## Реализованная область

Список по новой живой ссылке либо ссылке-снимку можно скопировать в свой private
список: выбранную укладку, вещь в сумку, дерево сумки, её оболочку или вещь
в каталог. Сервер разрешает чтение чужого источника без присвоения его журнала
и без права записи. Источник остаётся неизменным.

`list.import.body.serverImport` хранит собственный тип источника `shared-link`,
ID ссылки, режим, revision содержимого и hash точного выбора. Для live используется
revision исходного private списка, для snapshot — revision снимка. GET возвращает
`serverCopySource` отдельно от бизнес-данных; чтение работает при выключенном
writer и не создаёт файлы. Внутри используются общие детерминированные планировщики,
но в журнале и запросе не подменяется тип источника на публичный шаблон.

До ожидания сети фиксируются исходный снимок, версия назначения, область,
новые UUID укладок/владельцев/фото, размещение и метаданные. Затем сохраняются
точные оригиналы и миниатюры, полное действие и связь с очередью. Принятый
результат проверяет ID-карты, фото, hash файла, hash миниатюры и полный снимок.
Сервер проверяет исходные файлы и права под упорядоченными блокировками вместе
с целью. Ошибка квитанции откатывает бизнес-запись и revision.

Последующие поля и явное удаление используют `photoResults.version = 12`:
они ссылаются на исходную копию и непосредственного предшественника. Восстановление
при потере ACK читает прежние квитанции. После COMMIT источник может исчезнуть;
принятая копия и её продолжения остаются независимыми. Повтор не создаёт новый ID.

Журнал `bike-packing-server-selections-v1` сохраняет подготовленные и альтернативные
выборы отдельно от публичных шаблонов. Поддержаны выбор среди незавершённых
подготовок, проверка результата, отмена точного действия и файловых стадий,
потеря ответа при отмене, поздние локальные файлы и нехватка места. Сырые записи
входят в recovery ZIP как `server-import-selections.json`. Подтверждение не
разрешает удалять исходные байты. Смешанные подготовки разных типов разрешаются
по отдельности; приложение не выбирает победителя по порядку UUID.
