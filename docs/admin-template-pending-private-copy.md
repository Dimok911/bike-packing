# Личная копия из ожидающей правки административного шаблона

11.09.2026. Продолжение FE `1d392fda`; BE `8d011e8` только локально. Публикации нет,
исходные флаги OFF. Проверена обратная связь: сохранённая правка

без файлов. Общий административный раздел остаётся открытым.

## Неизменный выбор

Источник читается из проверенного административного плана, а не из текущего
ответа сервера. Выбранные данные, новые ID и личное действие сохраняются в
настоящем личном контексте до продолжения административной очереди. Затем
интерфейс открывает исходный административный редактор, продолжает его прежний
план и возвращает личную копию. Изменение аккаунта, экрана, исходных данных или
выбранного действия останавливает это продолжение. Оно не подменяет родительский
UUID после конфликта и не возвращает пользователя с другого экрана.

Источник `admin-template` содержит либо прежнюю подтверждённую `stateRevision`,
либо `base.operationId`; одновременная передача запрещена. Полный хеш выбранного
исходного содержимого обязателен в обоих вариантах. Административный UUID
хранится в `publicImport.source`, не в личном `causal.dependsOn`; у ожидающего
источника `causal.reads=[]`. Тело сохранённого личного действия не меняется после
получения серверной ревизии.

Сервер берёт административную блокировку каталога, личное действие и
отсортированные блокировки источника/назначения. До бизнес-изменений он
проверяет квитанцию отдельного административного журнала: аккаунт, среду,
шаблон, UUID, успешный результат и актуальную ревизию. Копирование дополнительно
проверяет права администратора, язык и точный полный хеш содержимого.
Ожидание не меняет личные данные. Отменённый, отклонённый, удалённый или
изменившийся источник не становится подтверждением для копии.

Новая отправка и повтор `waiting` требуют отдельного флага
`PERSONAL_PENDING_ADMIN_TEMPLATE_IMPORT_ENABLED` и capability
`personalCausalPendingAdminTemplateImportV1`. Старый клиент/сервер не включает
их случайно. Холодное чтение уже сохранённого выбора и точной терминальной
квитанции остаётся доступно; неизвестный результат личной отправки не разрешает
её повтор. Административный журнал сохраняет свой прежний контракт: после чтения
квитанции допустим повтор ровно того же UUID и тела; сервер применяет его один раз.
После reload кнопка продолжения сохранённой формы также продолжает точный
ожидающий административный план в его настоящем контексте, затем личную копию.

## Восстановление отдельного черновика

Найден и исправлен общий дефект `restorePublicCopyBusinessView`: восстановление
точного личного содержимого удаляло административный черновик, ранее добавленный
из зеркала. Холодный запуск со смешанным снимком также мог отвергать его как
личный импорт. Теперь из входного снимка выделяется только проверенное
административное пространство своего аккаунта; личная часть восстанавливается
дословно, затем добавляется актуальный административный черновик.

Это не обычная сериализация для отправки: она могла бы нормализовать фото,
словари или отметки упаковки. Новый узкий helper сохраняет эти данные,
размещения и неизвестные поля без преобразований. Чужие записи, конфликт ID
или ссылки между пространствами требуют сверки и не удаляются молча.

При восстановлении личный редактор остаётся заблокированным. Обычное сохранение
его зеркала не обходится: отдельное продолжение меняет настоящий контекст и
сохраняет в зеркале только четыре подтверждающих поля выбранного шаблона.
Личные данные и другие административные черновики берутся из актуального
зеркала без изменения. Более новая правка выбранного шаблона с тем же source
маркером также останавливает запись. При сравнении сохраняются полные
arrangement/фото/неизвестные поля, исключаются лишь производные связи, которые
меняются при открытии укладки. Ошибка хранения сохраняет квитанцию и возвращает
личный контекст для дальнейшей проверки.

## Границы

Файлы, одновременно ожидающее личное назначение и неоднозначные ID новой
административной копии сюда не входят. Для новых копий с несовпадающими ID
редактора/сервера требуется сначала подтвердить создание источника. Ожидание
фотоформ/импортов, административные файловые формы и ZIP, хранение старых данных
и общая приёмка остаются отдельными незавершёнными пунктами.
