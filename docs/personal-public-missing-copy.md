# Только недостающие вещи из публичного дерева

Локальное продолжение раздела 07, 2026-09-09; целевая приёмка завершена.
Публикация и рабочие флаги выключены. Используется существующий выбор
«Только недостающие» в окне копирования дерева из shared/demo-шаблона.

Режим добавляет отсутствующие вещи в найденные личные сумки. Он сохраняет
все свойства и фотографии существующих вещей и сумок, их размещения,
количества и отметки упаковки. Новые сумки не создаются. Вложенная вещь
попадает в соответствующую существующую вложенную сумку; если такой сумки
нет, действует прежнее правило добавления в найденный корень. Если ни одного
назначения нет, пустое действие не создаётся.

Сопоставление использует общие функции действующего интерфейса: исходные ID,
происхождение копии и сравниваемые свойства. Размещения и количества для
сравнения берутся из выбранных канонических укладок. Неизвестные свойства
строки размещения не подменяют свойства сумки. Порядок списка добавлений
фиксируется в момент выбора и не пересчитывается по свежему серверному списку.

Публичный импорт сохраняет свой контракт `publicImport.version: 2`;
`copy.version: 2, mode: "missing"` содержит полный исходный выбор дерева,
целевую укладку и точные пары `sourceItemId → targetContainerId`. Полный
`sourcePayload`, источник/язык/числовая версия, все новые owner/photo/asset ID
и метаданные сохраняются прежним журналом. `ownerTargets` включает только
новые вещи. Файлы существующих владельцев не загружаются и не заменяются.

Сервер заново проверяет состав по замороженному источнику и исходной версии
цели и требует точного совпадения всех добавлений и полного результата.
Сокращение, перестановка, добавление дубликата или другое назначение отклоняются.
Проверка публичного источника, файлов, private-цели, бизнес-эффект и квитанция
остаются одной транзакцией. Отмена/повтор/продолжения используют тот же
публичный протокол; операция не переименовывается в гостевой импорт.

Для «Дублировать всё» и «Только недостающие» составы и ID готовятся до окна
подтверждения отдельно. Ошибка подготовки одной альтернативы не разрешает
заменить её другой; пригодная альтернатива остаётся доступной. Нехватка места
сохраняет подготовленную копию и native-файлы, прежнее окно и экспорт.
