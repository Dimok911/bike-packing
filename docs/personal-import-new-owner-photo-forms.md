# Создание карточки сразу с фото во время переноса

Продолжение разделов 02–04, 06 и 09 от 10.09.2026 принято локально.
Код, общий API-контроль и проверка очистки черновика сохранённой формы готовы.
Рабочие флаги выключены; публикация и push не выполнялись.

## Поведение

Новая вещь или сумка во время ожидающего гостевого переноса/личного архива
получает одно действие с полями, размещением и полным набором новых файлов.
Отдельное предварительное создание пустой записи не требуется. Последующие
правки, удаление и следующая форма сохраняют исходную цепочку. Неизменяемые
номера и данные переживают перезапуск, потерянные ответы и повторные нажатия.

Новый ID должен отсутствовать во всех сохранённых предшественниках, в
подтверждённом результате родителя и в обеих серверных таблицах владельцев.
Сервер проверяет таблицы под блокировками внутри транзакции списка, включая
записи об удалении. Старую вещь нельзя создать повторно или превратить в
новую сумку под прежним ID. Ошибка SQL откатывает транзакцию и не превращается
в постоянное отклонение корректного действия.

После удаления владельца общая цепочка остаётся доступна для восстановления
и создания другого нового владельца. Редактирование удалённого владельца
и повторное использование его ID по-прежнему запрещены.

После устойчивого сохранения новой формы удаляется её прежний черновик
в каталоге. Создание передаётся явным признаком из выбранной формы, поскольку
символическая версия владельца равна `null`, а не числу `0`. Неуспешное
сохранение не очищает черновик; исходные фото в журнале не удаляются.

## Протокол и включение

- `ownerResult.version = 4`, `owner = null`: доказательство отсутствия нового
  владельца у точного родителя; сохраняются `operationId`, `importOperationId`,
  `importKind` и полный `pendingPhotos` исходного импорта.
- В неизменяемом запросе `baseEntityRevision = null`. После проверки
  отсутствия сервер использует `0` только во внутреннем исполнении.
- DB-потомок нового файлового действия использует `photoResults.version = 10`.
  Ссылка принимается только для результата с `photoForm.created = true`.
  Прежний v9 требует `created = false`; эти виды нельзя подменять.
- Клиент: `PERSONAL_IMPORT_NEW_OWNER_FORM_ENABLED = false`.
  Сервер: `BIKE_PACKING_CAUSAL_IMPORT_NEW_OWNER_FORMS_ENABLED`.
  Возможность: `personalCausalImportNewOwnerFormsV1`.
- Проверяются также обычные фотоформы, весь выбранный вид импорта и его
  потомки. Старые флаги или поддержка другого вида импорта не разрешают
  захват транспорта/файла, отправку либо отмену нового действия.
- Выключенные писатели сохраняют чтение и экспорт прежних записей.

Это продолжение guestImport v1 / archiveImport v2. Публичные копии,
административные формы, производитель и старые архивы v1 остаются отдельными
направлениями. Временный пустой владелец используется только в общей чистой
проверке состава фото; в запросах, файлах и серверных результатах его нет.
