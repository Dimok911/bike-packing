# Experiment v1614: восстановление сохранения владельцем общей укладки

В v1613 обычное сохранение собственной укладки visibility=shared получало 403 personal_owner_only. После неизвестной квитанции клиент сохранял исходное действие, но не мог возобновить отправку. Загрузка списка и доступность европейского API не подтверждали запись изменений.

Парный серверный выпуск f348040e разрешает обычный list.update владельцу shared/user-укладки. Проверки владельца, административных пространств, версий, фотографий и квитанций сохраняются. Новый маршрут /list-operations/:id/prepare под теми же блокировками регистрирует исходный UUID и digest без выполнения действия. Он ограничен корневым обычным обновлением, без зависимостей, чтений и принудительной перезаписи.

Клиент может начать подготовку только для сохранённого неизменного действия после проверки аккаунта, контекста, журнала и новой серверной возможности personalListOperationPreparationV1. Перед исполнением требуется отдельный GET с точной сохранённой записью owner_update_prepared. UNKNOWN, потеря ответа или ответ prepare сами по себе повтор не разрешают. UUID и исходная очередь не заменяются.

В исходниках новая функция выключена. Профиль публикации включает её только на https://experiment.vniipo-help.ru. Production не включается.

Проверки включают старый реальный формат журнала v1613 после 403, цепочку трёх размещений со старыми фотографиями, потерю ответа подготовки, одновременные запросы, изменение владельца/контекста/журнала и отключённые возможности. Приёмка действительной очереди в Chrome и телефона отдельно фиксируется после публикации. Это исправление обычного размещения не завершает весь переход и не добавляет редактирование старых файлов фотографий.
