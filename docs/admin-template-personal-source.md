# Копирование из личной укладки в административный шаблон

Продолжение 11.09.2026 после FE `4921d46`. Серверный срез `6874754` сохранён
только локально; runtime `ef05630` после `444808c`. Сайт и API не публикуются,
исходные флаги выключены. Приёмка всего перехода остаётся 2/12, admin 0/10.

Обычный выбор целевой укладки в формах вещи и сумки теперь подготавливает
копию из подтверждённого личного списка в выбранный demo/shared-редактор.
Поддерживаются отдельная вещь, дерево с содержимым, пустая сумка, карман и
добавление недостающих вещей в сопоставленные сумки. Источник сохраняется.
Размещённая отдельная вещь копируется количеством 1; дерево сохраняет количества
размещения. Подготовленный личный каталог хранит количество 1. Старый серверный
снимок с иным каталожным количеством требует сверки, копия его не исправляет.
Чистый планировщик и API отдельно сохраняют количество вне укладки из точного
переданного источника; это не отменяет предварительную проверку браузера.

До подтверждения читается полная серверная версия личного списка. Проверяются
аккаунт, текущий личный режим, отсутствие ожидающих правок, номер версии и точное
совпадение бизнес-данных. Служебные поля показа отделяет прежний
`personalBusinessPayload`; произвольная нормализация не заменяет сверку.
Новые ID, оба снимка и выбранный вариант фиксируются до записи. Пока окно
открыто, изменение источника, цели или аккаунта останавливает этот выбор.

Административный `template.save` получает отдельное доказательство чтения
`kind: personal-list`: ID личного списка, revision и SHA-256 полного серверного
снимка. Требуется дополнительная возможность сервера
`adminTemplatePersonalSourceSaveV1`. Старый сервер не получает такой запрос.
Личная очередь не становится писателем шаблона; сохраняется административный
план v4 с исходным UUID и отдельными версиями источника/цели.

Сервер проверяет права администратора, личное владение, приватность, тип списка,
сохранённый номер версии и отсутствие удаления. Проверка источника, запись цели
и квитанция выполняются в одной транзакции. Порядок блокировок согласован с
личными операциями. Чтение подготовки не создаёт строки, журналы или версии,
включая выключенный режим записи. Старое подтверждение после удаления источника
и следующей правки цели возвращает прежний результат без восстановления данных.
