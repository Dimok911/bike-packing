# Готовность и сохранность ввода справочника

CI `d653d83` / `34520315971` выявил отдельный сбой: при добавлении категории
WebKit завершил `fill`, но поле оказалось пустым. Страница не падала, ошибок
JavaScript нет. Первоначальная гипотеза о перерисовке этого конкретного поля
не подтвердилась: в локальном воспроизведении узел был прежним и подключённым,
но событий ввода не было. Открытый `personalSaveRecoveryDialog` блокировал
нативный фокус, пока приложение проверяло сохранённые данные.

Тестовый `synchronize` теперь ждёт не только серверного результата и чистой
очереди, но и закрытия этой проверки перед следующей правкой. `fill` сам по себе
не проверяет доступность поля поверх модального окна. Дополнительно проверяется
введённое значение до отправки. Таймауты, число повторов и ожидаемый результат
операции не ослаблены. Это исправление готовности тестового интерфейса.

Отдельный тест обновления между focus и native input проверяет приложение.
Редактор теперь обновляет части настроек, оставляя поля и их родительские
элементы подключёнными к документу. Кнопки заменяются и получают обработчики
для текущего владельца; поле переименования сохраняется только для того же
исходного значения. Поздний native input попадает в живое поле. Прежние границы
черновика сохраняются: аккаунт, список, личный/административный владелец и
точное исходное имя при переименовании. Отмена, сохранение или переход в
режим чтения не восстанавливают чужой либо уже принятый ввод.

Повторная привязка клавиатуры переименования сначала снимает прежний обработчик:
Enter после нескольких обновлений выполняет одно действие. Повторно используемое
поле не получает старое значение или выделение поверх уже начавшегося ввода;
первичное выделение названия выполняется только для нового поля. Иначе обновление
между focus и вводом дописывало новое название к прежнему — два сценария первого
UI-прогона воспроизвели это и потребовали дополнительного исправления.

UI-набор отдельно проверяет отсутствие отсоединения поля или его предков через
MutationObserver. Сохранность DOM и ожидание закрытия проверки — независимые
условия; одно не заменяет другое.
