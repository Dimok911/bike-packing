## Исправление ложного восстановления фотографий

новая сумка блокировалось окном «Фото требуют проверки», хотя фотодействий ещё
не было. Переключение нормализовало arrangement второй укладки, пока проверка
журнала ждала Web Lock. Проверка контекста остановила устаревшее чтение правильно,
но вызывающий код ошибочно сделал эту остановку постоянной ошибкой хранения.

аккаунта/списка/режима не разрешает принять старый результат. Настоящие ошибки
хранения и повреждённые записи не становятся поводом для автоматического повтора.

## Кнопки публикации, снятия публикации и удаления из списка

При включённом тестовом административном флаге снятие публикации и удаление из
списка используют сохранённые команды `template.publication` / `template.archive`.
Повтор команды после reload находит исходный план и сохраняет его UUID и версии
затронутых индексов. Новый выбор остаётся отдельным следующим действием.
Публикация через настоящую кнопку проверена как два действия: сохранение, затем
публикация с зависимостью от подтверждённого сохранения.

После подтверждения и перезагрузки завершаются только оставшиеся местные
изменения интерфейса. Для этого повторно проверяется сохранённая запись операции
и квитанция с её хешем, видом действия и версией результата. Одних локальных
флагов видимости недостаточно. Повреждённое подтверждение оставляет черновик и
окно открытыми, не создаёт новый запрос. Смена редактора при чтении исходного
плана также останавливает повтор без изменения сохранённого плана.

## Порядок административных шаблонов

Окно получает исходные версии до перестановки. Целый выбор и все номера
`template.metadata` сохраняются одной записью до первой отправки. Общая блокировка
аккаунта не даёт другой вкладке заменить незавершённый выбор. После обрыва окно
восстанавливает этот выбор; подтверждённые части не отправляются повторно.
Локальная отметка завершения принимается только с проверенными квитанциями всех
частей. Конфликт останавливает пакет и сохраняет результат для явной сверки.

Порядок шаблонов меняется в административном редакторе, личных укладок — в личном.
Таким образом административный пакет не отправляет личные записи через чужой
контекст. Обычный autosave после подтверждённой перестановки не добавляет лишнее
полное сохранение шаблона. Открытый редактор принимает подтверждённую версию и
значение порядка; следующая правка их сохраняет. Дополнительно устранена старая
потеря `layoutOrder` при открытии demo. До исправления модульный пример терял 17;
после исправления это значение сохраняется при открытии и обратном экспорте.

- `resume-admin-order-unit-3.txt`: 27/27, пакет, прежний порядок и преобразования.
- `resume-admin-order-ui-5.txt`: 12/12, demo/shared, подтверждение, повтор/reload,
  следующая правка на новой версии с сохранением порядка, оба браузера.
- `resume-admin-order-ui-6.txt`: 4/4, нехватка места и конфликт сохраняют выбор,
  окно и исходные номера, не повторяют подтверждённые или отклонённые действия.

той, которую администратор просмотрел; для опубликованного шаблона окно
предупреждает, что сохранённое содержимое станет видно пользователям.

После потери ответа, сбоя записи плана или reload продолжается прежнее действие
с исходной серверной revision. Изменившийся сервер отклоняет этот перенос;
повтор не подставляет свежую версию. Повреждённый выбор, смена местного содержимого,
контекста, отсутствие/удаление источника и неоднозначный прежний журнал требуют
сверки. Черновики другого административного контекста не конвертируются.

- `resume-admin-legacy-unit-1.txt`: 10/10, включая две вкладки, смену аккаунта,
  маршрута/прав/местного варианта, повреждение и недоступный серверный источник.
- `resume-admin-legacy-ui-1.txt`: 24/24, demo/shared, Chromium/mobile WebKit,
  перенос, обрыв ответа, отмена, квота записи выбора/плана и серверный конфликт.
- `resume-transport-7.txt`: 1114/1114; `resume-admin-legacy-source-1.txt`: exit 0.
- `resume-admin-legacy-ui-2.txt`: 42/42 после подключения реального списка
  выбора и восстановления предыдущего административного маршрута. Включает
  прежние 14 сценариев создания и 28 сверки старых черновиков в обоих браузерах.
- `resume-admin-legacy-source-2.txt`: exit 0; `resume-critical-5.txt`: 896/896.
- Общий административный UI: `resume-admin-all-ui-10.txt`, 128/128, оба браузера,
  7,6 минуты, без retries. Включает новые/старые черновики, порядок, сохранение,
  формы сумок/вещей, параметры, публикацию, снятие публикации и архивирование.
  Предыдущий `-9` остановлен для исправления обнаруженного прямого открытия
  старого черновика через список без сверки; он не объявляется полным проходом.

После общего прогона добавлен запрет неявного выбора одного из двух местных
черновиков той же канонической цели. Все варианты сохраняются, отправки нет;
ранее `find` мог выбрать первый, хотя пользователь открыл другой. Этот крайний
случай проверен вместе с целевым набором новых/старых черновиков отдельно:
`resume-admin-legacy-ui-3.txt`, 46/46, оба браузера, 2,8 минуты, без retries.
`resume-admin-legacy-source-3.txt`: exit 0. Полный прогон 128/128 выше предшествует
только этой последней защите от неоднозначной местной цели.

Это перенос явно выбранного местного варианта, а не полный интерфейс разрешения
любого конфликта. Выбор серверного варианта, отмена уже отправленных цепочек,
неоднозначные старые журналы, отсутствующие цели, копии/файлы и retention открыты.
Запись решения не очищается автоматически; исходные версии сохранены.

Публикаций, включения флагов и изменений живого API нет. Шесть отложенных файлов
галереи из прежней работы не входят в эти исправления.
