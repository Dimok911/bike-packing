# Личная копия публичного шаблона — переход в работе

Срез 2026-09-09. Рабочие флаги выключены; публикации нет.

Выбранный публичный источник фиксируется полностью: payload, канонический
itemKey/listId, числовая версия и язык. Новые укладки, владельцы, фотографии и
файловые действия получают собственные ID до подтверждения/чтения файлов.
Запись источника, полного действия, оригинальных файлов и очереди предшествует
изменению личного экрана. Сбой оставляет исходные данные для восстановления.

Действие `list.import` несёт собственный `publicImport`, отдельный флаг и
`personalCausalPublicImportV1`. Общие чистые правила формирования независимой
копии используются внутри реализации; гостевой wire-контракт не отправляется.
Публичный список указан в `causal.reads`, личная цель проверяется отдельно.

В одной транзакции сервер проверяет доступность/версию источника, полный
выбранный снимок, реальные байты исходных фотографий, личное владение целью,
отсутствие коллизий новых ID и весь набор готовых файлов. Ошибка оставляет
бизнес-таблицы без частичных изменений. Публичный читатель не создаёт и не
присваивает административный operation head. В этом режиме чтение полного
публичного снимка не запускает ленивую миграцию. Терминальная квитанция
сохраняется после изменения/удаления источника и даже удаления личного списка.

Отмена использует исходные ID и отдельное подтверждение «оставить серверную
версию». Неопределённый результат собственного файла допускает только отмену
его точного владельца с проверкой actor/list/operation/photo/asset/hash;
обычный импорт и посторонняя запись остаются запрещены.

Журнал выбора и действия неизменяемый, с проверкой хешей и блокировкой только
своего actor/list. Чтение и экспорт доступны с выключенными writers.
Подтверждённый терминальный маркер переживает уплотнение очереди. Локальное
восстановление промежутка между файлом и очередью связывает прежнее действие,
не перечитывает источник и не меняет отображаемый редактор.

Проверено на текущем серверном ядре:

- 260/260 API/MySQL, включая 8 новых проверок публичного импорта: собственный
  выключенный gate, копии с файлами/без файлов, отмена, lost ACK, перезапуск,
  SQL-откат последней записи квитанции, изменение версии/публикации/байтов
  источника, повтор после удаления источника и цели. 360,15 с.
- 95/95 серверных operation-проверок; 3 новые группы проверяют отсутствие
  записи в административный head и привязку реальных исходных файлов.
- 22/22 целевых frontend-проверки: полный frozen source, native codec, очередь,
  журнал, quota, смена контекста, терминальная квитанция и локальное связывание.
- 27/27 transport-проверок, включая отдельную отмену public/guest/archive
  и запрет смешанных конвертов/посторонних неопределённых файлов.

- 8/8 браузерных проверок реальной кнопки: с фото и без, подтверждённый ответ
  и потеря ответа с перезагрузкой, Chromium и мобильный WebKit. Полный
  выбранный снимок сохраняет отсутствующие необязательные поля: загрузчик
  экрана не превращает значения по умолчанию в новую бизнес-правку.
- 661/661 transport и 896/896 critical; проверка исходников пройдена.
- 14/14 контрольных браузерных проверок: собственный выключенный флаг
  публичной копии, гостевой перенос и обычная фотоформа, оба браузера.
