# Причинная копия целого административного шаблона

Проверенный срез от 10.09.2026: целый подтверждённый demo/shared шаблон без
файлов копируется в новый частный административный черновик. Источник не
изменяется. Backend: `44d2e09`. Работа локальная, публикаций нет; рабочие флаги остаются OFF.
Это часть раздела 11, а не закрытие всего направления копирования.

## Источник и результат

`template.copy` имеет отдельную серверную возможность `adminTemplateCopyV1`.
Клиент требует её вместе с `adminTemplateCausalOperationsV1`; одного старого
разрешения на сохранение недостаточно. `base: null` допускает только новую
цель. Тело содержит namespace/ID источника, подтверждённую `stateRevision`,
SHA-256 его канонического полного снимка и метаданные новой копии.

UI читает источник через административную подготовку и сравнивает revision
с открытой в редакторе. Незавершённая правка/операция источника блокирует
копирование; более старая опубликованная версия не подставляется. После
каждого ожидания проверяются аккаунт, режим, редактор и выбранный снимок.

Сервер проверяет административные права, канонические namespace, существование,
видимость, revision и digest источника под общей блокировкой каталога и строк.
Копия, история и квитанция записываются одной транзакцией. Утрата права или
ошибка записи квитанции откатывает результат. Повтор успешной операции возвращает
прежнюю квитанцию, даже если источник впоследствии удалён. Изменившийся источник
даёт устойчивый конфликт; новый источник для того же UUID не выбирается.

Сервер сам строит копию из проверенного снимка. Общая чистая функция frontend/
backend создаёт постоянные новые ID по UUID операции и отсортированным ID
источника. Переносятся каталог, вложенность, деревья вне укладки, размещения,
количества, упаковка, порядок, язык и справочники. Служебные поля редактора и
принадлежность старому шаблону исключаются. Недостающие ссылки, циклы родителей,
несколько укладок или индекс каталога требуют отдельной подготовки. Новая
серверная цель всегда `private`, revision 1; публикации в этой операции нет.

## Сбой хранения и восстановление

План v3 удерживает исходный снимок, операцию и отдельный нормализованный снимок
редактора. Последний нужен для сравнения после ACK: UI-экспорт нормализует ID
укладки и значения по умолчанию, тогда как сервер получает исходную проекцию.
Полный план защищён digest; digest источника дополнительно сверяется при
сохранении и чтении журнала.

До отправки создаётся проверенное локальное зеркало с `adminCausalCopyPlan`.
Если зеркало не записалось, новые местные сущности убираются и POST отсутствует.
Если зеркало записалось, а журнал операции — нет, тот же черновик сохраняет
весь план через reload. Открытие редактора или окна синхронизации завершает
подготовку с прежними UUID и снимками. Пока подготовка не завершена, обычное
сохранение/создание и другие команды не могут обойти её. Двойное нажатие кнопки
создания не запускает вторую копию.

## Границы

UI проверен для копии того же вида (demo → demo, shared → shared). Серверные
перекрёстные направления проверены отдельно; это не заявление о готовом
переключателе типа в UI. Источник с фотографиями отклоняется явным
`template_photo_package_required`: файловый адаптер ещё не подключён, фото
не удаляются ради успешной записи. Источник с незавершённой операцией пока
нужно дождаться; зависимости на ещё не подтверждённое чтение остаются открыты.

Дальше: отдельные вещи/сумки/деревья, массовые копии, связь существующего и
добавление недостающего, переходы личное ↔ административное, фото и архивы.
Также остаются неоднозначные старые журналы/связи, хранение и общий аудит.
Общая приёмка прежняя: **2/12**, административная **0/10**.
