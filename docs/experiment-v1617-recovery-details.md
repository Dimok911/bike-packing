# Experiment v1617: понятная сверка сохранённых изменений

В migration-ветку перенесены изменения из `e9bb4333b0daf8d64b473bde307ed381b90a4eef`.
Версия ветки, release profile и существующие feature gates сохранены. Описанные
ниже проверки выпуска относятся к отдельному release checkout; этот локальный
backport не выполняет сборку, браузерный прогон или публикацию.

Когда автоматический rebase не завершился и проверена более новая версия той же
личной укладки, под заголовком появляется обычное сообщение с кнопкой
«Разобрать изменения». Оно не закреплено при прокрутке и не открывает окно само.
Успешный rebase с подтверждённым сохранением убирает сообщение.

В окне показано описание каждой сохранённой записи вместо одного числа. Для
команд размещения используются записанное намерение и названия из той же
операции: например, добавление существующей сумки в конкретную укладку с её
содержимым. Удаление размещения не называется удалением самой вещи или сумки.
Для старых записей описание восстанавливается только по точной сохранённой базе
или непосредственному предшественнику той же цепочки. Если достоверных данных
нет, окно сообщает об отсутствии подробного описания.

Причина остановки передаётся отдельными разрешёнными полями. Отсутствие базы
указывается только после соответствующей проверки outbox; неизвестная причина
не объявляется конфликтом. Текст пользователя выводится через textContent.
Количество записей не приравнивается к количеству нажатий пользователя.
Записи с проверенным подтверждением сервера используются для сравнения, но не
выводятся в списке изменений, ожидающих решения.

Протокол, допустимые команды и решения восстановления не меняются. Просмотр,
экспорт и «Решить позже» не отправляют и не отменяют действия. Загрузка серверной
версии использует прежнюю последовательность сохранения исходной копии и
подтверждения остановки старых действий. Сообщение привязано к текущим владельцу,
области хранения и укладке.

Проверки выпуска: unit-тесты описаний и DTO, обычная release-сборка в Chromium и
mobile WebKit, source/critical/transport, контракт обоих API и пять файловых
сценариев публикации на Linux. Точные результаты и хэши хранятся в локальном
отчёте выпуска. GitHub Actions не используются; публикация только Experiment.
Восстановление настоящей очереди телефона требует проверки на самом устройстве.
Известная отдельная задержка гостевого запуска при ожидании фотографии остаётся
вне этого изменения.
