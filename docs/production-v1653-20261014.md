## Behavior and diagnosis

Reproduced the v1652 regression in the user's Chrome: summary requests returned
200, while the concurrent detail sweep received nginx 502 responses (reported
by Chrome as CORS/network failures). The old fallback displayed unverified
summary captions. A subsequent individual detail request succeeded, proved an
entry was technical-only, and the UI explicitly closed its newly opened modal.
This establishes the failure sequence; backend logs were not inspected, so the
underlying nginx failure cause is not asserted.

Details now load sequentially, stopping on the first failed or incomplete
comparison. Unverified summaries never become clickable history entries.
An initial failure offers Retry; a later-page failure preserves previously
verified entries and its existing pagination retry. Reopening clears the old
list before any catalog request. Details open after loading and cannot close
themselves merely because a technical entry was filtered. Server snapshots are
not deleted or modified.

The menu now offers one history mode: Local history for offline/guest work and
pending local actions; server History after successful synchronization. Local
history retains up to 20 actions after reload, shows changes and dates, and
supports confirmed undo of the latest action or a selected action together
with later local actions. Conflicting newer data blocks undo. Cancellation
leaves data unchanged, and an intervening journal/scope change invalidates a
pending confirmation. The last action's prior picture references stay protected.

A successful entity or full-payload save acknowledges the journal captured
before the save. Failure, blocked saves, another account, and actions created
while saving do not get erased. The separate new-layout entity save uses the
same acknowledgement. On account activation, legacy journal entries can be
trimmed to the confirmed local baseline; missing or incompatible baselines are
handled conservatively. No backend or shared service changed.
