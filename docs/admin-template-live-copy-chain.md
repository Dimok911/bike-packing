# Продолжение после копии без перезагрузки

Дополнение к `admin-template-pending-catalog-copy.md`, 11.09.2026.
Переход не публикуется, исходные флаги OFF.

После копии, созданной отдельным адаптером поверх ожидающей правки, координатор
мог сохранять в памяти захват предыдущей правки. Указатель редактора уже относился
к копии, но старый захват мешал принять подтверждение или захватить следующую
правку. Перезагрузка очищала эту память, поэтому прежние проверки с reload
не покрывали продолжение в том же окне.

Теперь адаптер после надёжной записи дочернего плана дожидается завершения
захвата предшественника и освобождает только соответствующую запись в памяти.
Контекст, объект редактора и ID предшественника должны остаться прежними;
более новый захват не удаляется. Все сохранённые планы и результаты остаются.
До сохранения нового указателя зеркало копии блокирует обычную правку; ошибка
записи указателя по-прежнему оставляет зеркало для восстановления.

Модульные проверки координатора: **24/24**, включая копию и следующую правку
до отправки, подтверждение всей цепочки в том же окне и защиту нового захвата.
Общие проверки: очередь **1280/1280**, critical **901/901**, source check exit 0.
Браузерный контроль **32/32**, 4,0 минуты: 8 новых сценариев через «Синхр.» →
«Продолжить отправку» → следующая правка и 24 проверки ошибок записи
плана/указателя/зеркала, оба браузера, без повторов и пропусков.
Журналы `resume-catalog-live-{unit-1,ui-2,transport-1,critical-1,check-1}.txt`
в `node_modules/.cache/causal-evidence/2026-09-08/`.

Первый браузерный набор: 7/8; один тест нажал «Синхр.», но не нажал
«Продолжить отправку» в открывшемся окне восстановления. Теперь тест явно
проходит эту последовательность, без изменения поведения интерфейса.
Ошибки Cache API и нативные падения WebKit остаются отдельными открытыми пунктами.
