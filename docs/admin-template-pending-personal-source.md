Публикации нет, флаги OFF. Подключены копия вещи и дерево сумки без файлов из

## Поведение формы и восстановление

Выбранные данные, новые ID и административный план сохраняются до ожидания
личной записи. Пока работает личная очередь, интерфейс сохраняет настоящий
личный контекст. После ожидания сверяются тот же аккаунт, список, выбранные
данные, точное действие очереди и квитанция. Новый UUID после согласования
конфликта не подменяет исходный выбор. Затем открывается административная цель.

Потерянный ответ проверяется по прежнему UUID через «Синхр.» после перезапуска;
после подтверждения можно открыть сохранённую цель. Если судьба отправки
остаётся `unknown`, повтор не выполняется, выбранная копия остаётся на устройстве.
Недостаток места при записи плана сохраняет предварительный выбор для reload.
Изменение источника после показа подтверждения отменяет применение выбора.

Исправлен обнаруженный общий дефект: startup fallback считал shared-редактор
без старого `adminTemplateCopy` временным и удалял его вместе с сохранённым
планом. Теперь наличие собственных `adminCausalSource`/`adminCausalCopyPlan`
исключает такой редактор из автоматической очистки, в том числе при повреждённом
маркере, требующем сверки. Личная сверка также сохраняет отдельный актуальный
административный namespace своего аккаунта; личные данные из зеркала не подмешиваются.

## Единое представление источника

Для `personal-list` с `base.operationId` хеш и `sourceSnapshot` содержат ровно
`personalBusinessPayload`: полные arrangement, количество, фото и неизвестные
бизнес-поля; исключены только перечисленные настройки вида и производные
размещения. Standalone-модули FE/BE идентичны. Полное исходное действие личного
журнала остаётся неизменным. Прежний хеш собранного серверного представления
для этой формы не принимается. Подтверждённые личные источники с `stateRevision`
и административные источники продолжают использовать прежний полный хеш.

Это устраняет найденное расхождение: реальный `serialize(forSync)` не содержит
display mirrors, которые сервер добавляет при чтении. API-тест теперь создаёт
настоящий forSync/outbox/helper источник, а не начинает с готового серверного ответа.

## Ранее проверенный серверный контракт

Административное сохранение с `source.kind: personal-list` теперь может
сослаться на UUID личного предшественника вместо номера версии. Клиент требует
отдельную возможность `adminTemplatePendingPersonalSourceV1` в дополнение к
прежним возможностям источника; старый сервер не получает такой запрос.
Точное тело и UUID переживают ожидание, потерю ответа и перезапуск клиента.

Сервер читает подтверждение из личного журнала для того же аккаунта и среды.
Проверяются список, вид действия, полный успешный результат и положительная
версия. Удалённый источник, отменённый/отклонённый предшественник и частично
принятый пакет не подтверждают копию. Чужой аккаунт и другой журнал с тем же
UUID не заменяют отсутствующее личное подтверждение. Ожидающее действие не
блокирует журнал до прихода предшественника.

После подтверждения предшественника сохраняются проверки владельца,
приватности, namespace, удаления, текущей версии и SHA-256 источника в
оговорённом выше представлении.
Цель имеет собственную независимую зависимость. Проверка чтения, запись цели
и квитанция остаются одной транзакцией. Чтение квитанции не берёт блокировку
строки предшественника; порядок блокировок списков не меняется.
Повтор уже принятой копии возвращает прежний результат после удаления
личного источника и дальнейшей правки цели, не восстанавливая старые данные.
