# Фотографии и видео укладки

Редактирование находится в существующем окне «Редактировать укладку», под
заметками. Выбор файлов, камера, вставка изображения или URL из буфера и
перетаскивание файлов/ссылок через существующий импорт изображений. Вещи и сумки
также получили область приёма с подсветкой при перетаскивании. Миниатюры с увеличением, отдельные
подписи, кнопки изменения порядка, удаление и одна ссылка HTTP/HTTPS на видео.
Видео открывается по ссылке, без встроенного плеера. Изменения применяются через
«Сохранить»; закрытие с отказом от сохранения оставляет прежние данные.

Данные: `layout.photos` (существующий формат фото плюс `caption`, до 2000 знаков)
и `layout.videoUrl`. Используются существующие лимиты фотографий на запись.
Добавлены пути синхронизации, кэширования, резервного копирования и копирования
укладок. Общая библиотека `/shared-ui/` не изменялась.

## Порядок будущей публикации

1. В репозитории bikepacking-api применить
   `docs/migrations/2026-09-26-layout-photos.sql` (расширение enum `entity_type`).
2. Выпустить API с поддержкой `entityType: layout`.
3. Проверить авторизованную загрузку и чтение фото через API с настоящей БД.
4. Выпустить фронтенд по обычной процедуре проекта, перенося только изменённые
   файлы приложения. Существующие фотографии повторно не загружать.

Миграция и публикация в рамках этой работы не запускались. При откате приложения
не сужать enum и не удалять уже загруженные фотографии укладок.

## Проверки

- `node --test tests/critical/layout-media.test.js`
- `npx playwright test tests/e2e/layout-media.spec.js tests/e2e/photo-input-methods.spec.js --project=chromium`
- `npm run check` в обоих репозиториях.
- В bikepacking-api: `node --test test/bike-packing-layout-photos.test.js`.

Результат: сборка и проверка синтаксиса прошли; 4 браузерных сценария прошли,
включая вставку фото/URL, перетаскивание с подсветкой в укладке, вещах и сумках,
подписи, порядок, сохранение, увеличение и отмену. В API прошли 70 проверок.
В полном наборе фронтенда прошли 919 из 920 проверок; причина оставшегося сбоя ниже.

В полном `test:critical` обнаружен существующий сбой проверки исходного текста
`empty item-copy target reuses the bag picker and resumes the same copy flow`:
она ожидает прежнее присваивание `const layoutId = getLayoutRootTargetLayoutId()`;
в рабочей копии до задачи уже добавлен приоритет `targetLayoutId || …`.
Этот сценарий не изменялся в задаче фотографий.
