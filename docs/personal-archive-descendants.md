# Правки после сохранённого файлового архива

Локальная реализация принята 2026-09-09. Публикации, push, live-миграций
и включения release gates нет.

## Поведение

После фиксации полного архива, замены выбранной укладки или импорта копии
пользователь может сохранить поля вещи/сумки и явно удалить владельца либо
укладку, пока файлы и исходный импорт ещё ждут подтверждения. Каждая правка
получает свой UUID и полный снимок до изменения экрана. Сам архив, его
источник, все привязки файлов, порядок фотографий и первоначальный UUID
остаются неизменными. Повторное нажатие в форме использует тот же результат.

Изменение самих фотографий, создание записи и составные изменения размещения
в этой форме остаются отдельными адаптерами. Этот документ описывает только
DB-продолжение сохранённого архива, не закрывает весь раздел 09 или весь список.

## Протокол

- False gate FE: `PERSONAL_PENDING_ARCHIVE_UPDATE_ENABLED`.
- False gate API: `BIKE_PACKING_CAUSAL_ARCHIVE_DESCENDANTS_ENABLED`; зависит
  от защищённого файлового импорта.
- Capability: `personalCausalArchiveDescendantsV1`.
- Потомок — обычный `list.update` с `photoResults.version = 3`, UUID исходного
  `list.import` и упорядоченными владельцами из `archiveImport.files`.
  Для импорта без новых файлов допустим `owners: []`.
- Зависимости содержат одновременно исходный импорт и непосредственного
  предшественника, с устранением только точного повтора одного UUID.
  Историческая связь checkpoint не используется как зависимость отправки.

Локальный журнал проверяет всю последовательность и неизменность ссылок.
Удаление владельца проходит общий явный reducer; удаление укладки сохраняет
всех владельцев, в том числе без фото. Удалённый импортированный владелец не
может вернуться в следующем снимке. Нельзя поменять порядок файлов, перенести
ссылку другому владельцу, добавить URL или подменить asset UUID.

API читает неизменяемые подтверждения исходного импорта и непосредственного
предшественника внутри обычного выполнения причинной операции. Проверяет
аккаунт, список, среду, числовые версии, весь ordered file/result inventory и
фотографии в родительском результате. Только отдельный снимок для выполнения
заменяет точные pending ссылки на подтверждённые. Исходное тело, его digest и
сохранённая квитанция не переписываются. Затем действуют обычные DB/photo
проверки, CAS, SQL-транзакция, история и tombstones.

## Восстановление

Отправщик сначала завершает исходные файлы и импорт, затем точных потомков.
Ответ более раннего действия не применяется к экрану. После подтверждения
последнего UUID читается актуальная версия сервера и атомарно сохраняется
checkpoint вместе с подтверждениями фото. Отдельная отметка applied ребёнка
не может обойти этот этап. Более новая серверная версия остаётся актуальной.
Все исходные бинарные данные сохраняются после подтверждения.

Явная отмена сначала запрещает исходному импорту исполниться, затем отменяет
неотправленные части и подтверждает отклонение каждого зависимого действия.
Выбор оставить серверную версию фиксируется отдельным новым действием без
archiveImport/photoResults. Потеря ответа и reload не создают новое решение
и не повторяют отправку уже принятых файлов.

При quota форма остаётся открытой. Экспорт восстановления включает и исходный
архив со всеми локальными файлами, и несохранённые поля формы; такой экспорт
не считается отправляемой операцией или подтверждением сервера.

- 188/188 API/MySQL на Node24.19, `archive-descendants-mysql-3.log`,
  222,24 с. Reverse delivery, fileless и новые файлы, последовательные поля /
  удаления вещи, сумки, последней укладки с замороженной заменой; lost ACK,
  reload/API restart, неизменность старых тел, SQL rollback, подмены ссылок,
  новая серверная версия, отмена всей цепочки с потерянным ответом решения.

  `archive-descendants-ui-2.log`, 9,3 минуты. Поля full/replace/copy; удаления
  вещи, сумки, укладки; quota с экспортом полей и оригиналов; lost child ACK;
  отмена цепочки с lost cancellation/decision ACK; прежние отмены архива.
  Предварительный UI run1: 16/16 за 6,5 минуты.
- 895/895 critical, 523/523 transport (`archive-descendants-transport-3.log`),
  63/63 operation, 74/74 source/service, FE source check-2.
- API run1: 181 pass / 5 fail из 186. Ошибка нового теста `queue.dispatch`
  вместо `queue.run` не дала включить тестовый capability; исправлен тест.

- После исправления тестовой формы последней укладки и усиления checkpoint
