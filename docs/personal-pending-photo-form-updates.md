# Действия после ещё не подтверждённой фотоформы

Локальный этап после FE e6f2fee / API b25873c. Обычная форма вещи или сумки
может иметь зависимые изменения полей, размещения и явное удаление, пока
её файлы или итоговая запись ещё не подтверждены. В частности, вещь можно
связать с только что созданной сумкой из окна выбора пустой укладки.
Исходные фотографии вещи и исходная укладка при этом сохраняются.

Новый `PERSONAL_PENDING_FORM_UPDATE_ENABLED` остаётся false. Нужны также
фотоформа, очередь и серверная capability `personalCausalPhotoFormDescendantsV1`.
Реализация не опубликована; режим включается только в изолированном тестовом
пакете через `BIKE_PERSONAL_PENDING_FORM=1`. Прежние режимы сохраняют свои ограничения.

Каждое следующее DB-действие записывается до изменения интерфейса и содержит
полный снимок, непосредственного предшественника и ссылку версии 5 на исходную
фотоформу. Цепочка проверяется целиком: аккаунт, список, среда, поколения,
зависимости, база и сохранённые данные. Исторический checkpoint не становится
причинной связью. Пропущенный или чужой предок, цикл, повтор ID и изменение
фотографий в DB-потомке не допускаются.

Файлы остаются у исходного действия. Потомки не загружают их снова и не
перезаписывают форму. Поддержаны новые фотографии, смесь старых и новых,
а также форма удаления/перестановки без новых файлов. Удаление владельца
явное; последующие действия не могут вернуть уже удалённого владельца.
Добавление новых файлов в следующей неподтверждённой форме остаётся отдельным
открытым этапом. Потомки копирования, архива и гостевого импорта используют
свои ранее реализованные протоколы.

Сервер подставляет ссылки на фото только из точного подтверждённого результата
исходной формы; запрос и историческая квитанция не изменяются. Перед исполнением
проверяется последняя подтверждённая версия непосредственного предшественника.
Поля, связи, фотографии, история и квитанция фиксируются одной транзакцией.
Клиент проверяет весь полученный бизнес-снимок: только точные ожидающие фото
могут получить серверные метаданные. Пропущенные поля, укладки, фото и иной
порядок не принимаются за подтверждённый результат.

Отмена сохраняет исходную форму, файлы и всех потомков. Сначала подтверждается
невозможность исполнения исходной формы и ещё не отправленных файлов, затем
отдельно закрываются зависимые действия. Только явный выбор текущей серверной
версии создаёт новое DB-действие. Выбор можно отложить и продолжить после reload;
потеря подтверждения отмены не создаёт повторную отправку фотографий.

Проверены 604 transport, 896 critical, FE check; API 81 operation и 74 source/service.
Реальный API/MySQL 230/230 (354,32 с), UI 30/30 (7,3 мин), дополнительно
потеря ACK окончательного выбора 4/4 (1,6 мин), регрессия с выключенным новым
флагом 18/18 (4,6 мин). UI проверен в Chromium/mobile WebKit; это не замена
проверки физического iPhone. Логи и исправления обвязки перечислены в
`continuation-2026-09-08.md`. API-коммит 1311c1a. Общие разделы 01–12 остаются открыты: этот этап
не подменяет фотографии из производителя/публичных источников, новые файлы
в неподтверждённой цепочке, администрирование, sharing и проверку на устройстве.
