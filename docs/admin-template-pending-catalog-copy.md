# Копирование внутри каталога с ожидающей правкой

Продолжение 11.09.2026. Локальный переход без публикации; исходные флаги OFF.

Одиночная и массовая копия вещей/пустых сумок внутри того же административного
шаблона может следовать за сохранённой, но ещё не подтверждённой правкой.
Копирование вещи в сумку или карман использует тот же путь. Выбранные записи,
снимок и новые ID фиксируются до подтверждения выбора. Перед изменением
редактора проверяются сохранённый источник, его хеш, точная цепочка и отсутствие
сохранённого решения об остановке.

Копия сохраняется отдельным `template.save` с исходной базой `{ operationId }`.
Она не берёт новую ревизию из позднего ответа и не меняет данные предшественника.
Восстановление промежуточной копии из локального зеркала допускает только
точный сохранённый план родителя в том же шаблоне; отсутствующий или отменённый
родитель блокирует продолжение. Остальные межшаблонные цели по-прежнему требуют
своего подтверждённого состояния.

Серверная проверка: **389/389**, 317,6 секунды,
`resume-pending-catalog-api-1.txt`. BE `31a99c9` только локально, runtime
`a631516` не менялся. 12 добавленных случаев проверяют одиночную/массовую копию,
обратную доставку, отмену предшественника, вмешавшуюся ревизию и перезапуск.

Отмена при уходе со страницы охватывает всю текущую попытку: ожидание
блокировки, проверку пользователя, чтение результата и отправку действия.
Следующий запрос не запускается после `beforeunload`/`pagehide`; ответ старой
попытки не принимается. Сохранённое действие и неопределённый результат POST
остаются для сверки по тому же ID. Повторная попытка в живой странице работает,
включая отменённый уход или возврат страницы. Проверки клиента: **22/22**,
`resume-pending-catalog-lifecycle-unit-2.txt`.

Предыдущие попытки обёртки Web Lock, явного обработчика fetch и отмены отдельного
запроса не устранили сбой и удалены. При отмене всей попытки повторный мобильный
набор дал **9 прошедших / 1 сбой**: прежнее сообщение Fetch больше не появилось,
но WebKit выдал `Cache API operation failed: Context is stopped` без JS-стека.
Это ранее воспроизведённый отдельным Cache API диагностическим скриптом сбой
при reload; он не отфильтрован и не объявлен исправленным. Все проверки данных
и ID прошли.

Полный набор `resume-pending-catalog-ui-3.txt`: **74 прошли / 3 ошибки / 23 не
запускались**, 7,1 минуты. Два отказа Chromium относились к сообщению квоты:
уведомление предыдущей неудачной отправки перекрывало новое. Только в этом
сценарии тест теперь дожидается сообщения исходной неудачной отправки до
копирования. Контроль всех вариантов квоты **8/8**, 1,4 минуты (`quota-ui-4`).
Третий отказ — описанный Cache API `Context is stopped` в mobile metadata.
Оставшиеся мобильные сценарии и этот случай прошли **24/24**, 2,6 минуты
(`ui-6`). Попытка `ui-5` не запустила тесты: временная ошибка Windows открытия
создаваемого файла каталога; следующая сборка прошла без изменений кода.

Итого **76 новых + 24 регрессионных уникальных UI-сценария** имеют успешный
контрольный прогон, оба браузера, без автоматических повторов/пропусков.
Полный набор не заявляется как чистые 100/100 одним запуском: прежние отказы
сохранены, непостоянный сбой Cache API остаётся открытым.
Общие проверки: очередь **1277/1277**, critical **901/901**, source check exit 0
(`resume-pending-catalog-{transport,critical,check}-3.txt`).

1486 прошедших, 292 пропущенных, 6 нестабильных, 1 ошибка. Обе попытки содержат `page-crash`, kernel подтверждает падения compositor;
подробности в `browser-ci-diagnostics-2026-09-10.md`. Регрессия фотоформы
не установлена, критерий WebKit остаётся открытым.
