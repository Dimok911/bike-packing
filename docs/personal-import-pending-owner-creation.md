## Поведение и границы

Во время гостевого переноса или восстановления личного архива новая вещь
или сумка без новых фото сохраняется одним действием вместе с размещением.
Для вещи фиксируются количество и доступность, для сумки — выбранная укладка
и родитель. Исходный импорт и его файлы остаются неизменными. После такого
сохранения новая карточка может получить фотографию через ранее принятый
адаптер фотоформ. Создание сразу с файлами остаётся следующим шагом.

Адаптер принимает только точную сохранённую цепочку guestImport v1 или
archiveImport v2. Публичные копии, старые архивы v1 и административные формы
не используют этот путь. ID новой записи отсутствует во всех сохранённых
предшественниках; нельзя повторно создать удалённого владельца под прежним ID.
Форма, размещение и ID фиксируются до асинхронной проверки исходных файлов.
Повторное нажатие возвращает то же сохранение. Изменение аккаунта, формы или
головы очереди останавливает попытку.

В очередь записывается обычный DB-потомок с прежними ссылками на результаты
импорта. Пустая фотооперация не отправляется: разрешение пустого состава
используется только для локальной проверки новой карточки. Сетевой декодер
по-прежнему отклоняет такую фотооперацию. Новых серверных методов нет.

При нехватке места диалог остаётся открытым, снимок новой формы доступен
для восстановления; ZIP также содержит исходные файлы переноса. После
перезагрузки используются прежние действия и ID. Рабочая публикация,
push и включение флагов не выполнялись.
