# Каталог сумок производителей

## Текущий охват

Снимок от 2026-08-29 содержит 87 самостоятельных моделей:

- ORTLIEB — 47;
- Arkel — 40.

Включаются самостоятельные велосумки и переносные сумки из официальных профильных разделов. Цвета, материалы и способы крепления одной модели хранятся как варианты SKU, а не как дублирующиеся карточки. Из охвата исключаются багажники, запасные части, внутренние органайзеры, отдельные сменные мешки без крепления и комплекты, которые только повторяют уже учтённые модели.

Исходные разделы:

- `https://us.ortlieb.com/collections/panniers-and-bike-bags/products.json?limit=250`;
- `https://us.ortlieb.com/collections/bikepacking/products.json?limit=250`;
- `https://us.ortlieb.com/collections/frame-bags/products.json?limit=250`;
- `https://us.ortlieb.com/collections/handlebar-bags/products.json?limit=250`;
- `https://us.ortlieb.com/collections/rack-top-bags/products.json?limit=250`;
- `https://us.ortlieb.com/collections/saddle-bags/products.json?limit=250`;
- `https://arkel.ca/collections/all-bags-and-panniers/products.json?limit=250`.

Для каждой модели сохраняются ссылка на официальную карточку, дата проверки, варианты SKU и одна локальная фотография шириной до 700 px. Длинные маркетинговые описания не копируются: в приложении используется короткое нейтральное описание на русском и английском. Неуказанные производителем характеристики остаются пустыми и в сравнении показываются как «Не указано».

## Обновление снимка

Сценарий `scripts/build-manufacturer-catalog.mjs` читает сохранённые публичные Shopify JSON и HTML карточек, нормализует типы, варианты и характеристики, затем создаёт `src/data/manufacturer-bag-catalog.generated.js` и манифест изображений. Сетевое скачивание отделено от production-сборки: приложение всегда собирается из проверенного локального снимка и не зависит от доступности сайтов производителей.

После обновления источников необходимо:

1. Проверить список исключений и распределение моделей по типам в сценарии.
2. Пересобрать сгенерированный каталог и локальные изображения.
3. Обновить дату снимка и ожидаемые количества в критическом тесте.
4. Запустить `npm.cmd run test:critical`, `npm.cmd run check` и `npm.cmd run build`.

## Добавление другого производителя

Для Shopify-магазина используется тот же путь: публичный `products.json`, официальные карточки товара и локальные изображения. В генератор добавляются отдельные правила бренда:

- список профильных разделов;
- исключения аксессуаров и дубликатов;
- соответствие модели единственному типу установки;
- разбор технического блока;
- домен источника и каталог изображений.

Для сайта без Shopify нужен отдельный адаптер получения данных, но итоговая схема остаётся той же. Это позволяет сравнивать модели разных брендов только внутри одинакового типа, не связывая frontend напрямую с разметкой стороннего сайта.
