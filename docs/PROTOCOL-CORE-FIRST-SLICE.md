# Первое извлечение ядра: доставка и подтверждение

15 сентября 2026. Локальный кандидат от опубликованного frontend v1622
`5f0bfdee841ac63037ded7e145173022884e540a`, ветка `codex/protocol-core-v1622`.
Карточка: https://trello.com/c/6B3JbblM. Полная карточка ещё не завершена.

## Что подключено

`src/protocol/confirmed-delivery.js` не импортирует Bike Packing, DOM,
хранилища браузера или Node. Модуль задаёт последовательность:

1. Долговечная запись нового неизменного намерения через адаптер capture.
2. Последняя синхронная проверка контекста перед отправкой.
3. Одна отправка и проверка/сохранение подтверждения через адаптер accept.
4. При неизвестном исходе — только чтение квитанции исходной операции.

Ошибка записи не разрешает отправку. Ошибка записи подтверждения не выдаёт
успех. Неизвестная квитанция не разрешает повтор POST. Серверный waiting
и отказ в доступе сохраняют свою отдельную обработку в адаптере приложения.

Существующая `src/sync/list-operation-queue.js` использует этот модуль в
общем пути первоначальной отправки. Поэтому выделенная последовательность
используется не только для переименования: другие уже включённые операции
также проходят прежний общий участок через модуль. Их предметные проверки,
допуски, отмена и возобновление подготовленных операций не переносились.

Первый предметный сценарий — payload переименования личной вещи с
неизменными фотографиями. Тип `list.update`, ID, payload, digest, серверный
контракт, журнал и проверки актуальности результата сохранены. На сервере
Bike Packing изменений нет. Получение квитанции не разрешает применить её
к другому аккаунту или более свежему экрану.

## Второй независимый пример

`examples/confirmed-notes/notes.mjs` — небольшое приложение заметок с
собственным HTTP-сервером, файловым хранением и форматом квитанций.
Единственный общий импорт — `src/protocol/confirmed-delivery.js`.

Запуск из этой ветки: `node examples/confirmed-notes/demo.mjs`.
Пример переименовывает заметку, теряет ответ после записи на сервере,
восстанавливает квитанцию, перезапускает сервер и клиент и снова читает
тот же результат. Итог проверенного запуска: committed / committed,
исходный ID сохранён, серверный эффект один. Каталог восстановления
выводится при запуске. Сервер привязан только к 127.0.0.1 и закрывается.

Это однопользовательский пример, а не сервер для публикации: нет системы
входа, ограничений срока хранения квитанций и производственной БД.
Замена файла сохраняет состояние и квитанцию вместе в обычной работе;
гарантия при отключении питания здесь не заявляется. Параллельная работа
нескольких процессов с одним каталогом не поддерживается.

## Проверено

Один целевой запуск:
`node --test --test-reporter=dot tests/critical/confirmed-delivery.test.js tests/critical/list-operation-queue.test.js`

67 тестов прошли. Проверки включают ошибку локальной записи, неизвестный
результат и холодное восстановление без повторной отправки, ошибку записи
квитанции, waiting/отказ доступа, смену аккаунта, HTTP-пример с сохранением
данных между перезапусками, действующие сценарии очереди Bike Packing.
Проверка переименования на уровне адаптера подтверждает неизменность
фотографий, payload и номера операции после потери ответа и перезапуска.

Один отдельный запуск demo прошёл. Vite build прошёл (31,96 с); сборка
выдаёт предупреждение о крупных чанках. `git diff --check` прошёл.
GitHub Actions и публикация не запускались. Проверка реального телефона
и живого API для этого нового кандидата ещё не выполнялась.

## Что ещё нужно для завершения карточки ядра

- Выделить общий договор хранения/поиска неизменного намерения и квитанции,
  включая идентичность операции. Сейчас их реализация остаётся в адаптерах.
- Перенести следующий необходимый участок возобновления очереди, сохраняя
  нынешние барьеры и проверку контекста. Не переносить всё за один раз.
- Проверить переименование через интерфейс собранного Bike Packing и
  нынешний сервер; затем принять на телефоне опубликованный кандидат.
- Зафиксировать границу серверного адаптера с существующим транзакционным
  журналом. Серверное ядро пока не выделено; пример не доказывает обратного.

Частичная загрузка, новые офлайн-настройки, маленькая команда item.rename
и оставшаяся интеграция фотографий не добавлены в этот шаг.
