## Problem and correction

After v1653 stopped concurrent history detail requests to avoid server 502s,
the dialog waited for every detail in a 25-record page before showing anything.
The user reported a long wait on iPhone.

Summary pages now request five records. Each verified user action appears as
soon as its comparison succeeds; later records continue loading sequentially.
Older pages remain available through Load more. Technical records stay hidden,
and unverified summaries are never shown. Daily checkpoints wait until page
completion because a verified same-day action may supersede them. A later
request failure preserves already verified rows and offers retry. Generation
guards prevent results from an older dialog/source from changing the current one.
