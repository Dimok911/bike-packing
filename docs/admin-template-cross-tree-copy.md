# Копия сумки между административными шаблонами

11.09.2026. Backend `444808c`, локально без отправки ветки.
Продолжение раздела 11 без публикации. Проверено копирование
дерева, пустой оболочки и вложенного контейнера между двумя подтверждёнными
demo/shared редакторами. Цель должна быть заранее открыта и подготовлена;
вариант с ожидающим источником, личными списками, фотографиями и «только
недостающее» этим этапом не закрывается.

Сохранение существующей цели использует `template.save` с дополнительным
`source`: каноническая пара itemKey/listId, исходная stateRevision и SHA-256
полного источника. Клиент требует отдельную возможность `adminTemplateSourceSaveV1`.
Прежние create/save/metadata не получают неявного источника. Источник другой
личной области, совпадение с целью и неподтверждённая operationId-база запрещены.

Сервер под общей блокировкой административного каталога проверяет обе строки,
версии, типы/доступность, hash источника и текущие права. Неизменённая цель не
позволяет проигнорировать изменение источника, и наоборот. При сбое откатываются
данные и квитанция. Повтор уже принятого действия возвращает прежнюю квитанцию
даже после удаления источника. Флаг административных операций остаётся OFF.

План v4 сохраняет исходный серверный снимок, итоговую цель, две версии и UUID
до отправки. Источник дополнительно проверяется по digest при чтении журнала.
Подготовка интерфейса проверяет оба редактора после каждого ожидания и перед
подтверждением. Новые записи принадлежат цели, количество берётся из размещения
источника, новые отметки упаковки не появляются. Полное зеркало с планом
предшествует переключению в целевой редактор. Сбой первого зеркала откатывает
местные изменения; следующие сбои должны продолжать тот же сохранённый план.
