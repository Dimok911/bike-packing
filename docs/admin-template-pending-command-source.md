# Копия после отдельной команды видимости или архивирования

Продолжение 11.09.2026. Без публикации перехода; исходные флаги OFF.

Отдельное снятие публикации и архивирование не переписывают состав шаблона.
Ожидающая копия вещи, дерева или целого шаблона теперь получает данные из
точного исходного снимка либо сохранённого предшественника, а зависимостью
назначает UUID этой отдельной команды. Поддерживается и цепочка после
метаданных: серверные данные и нормализованный редактор сверяются отдельно.

Изменять только локальный флаг видимости недостаточно. Требуются проверенный
план команды, его полная цепочка и совпадение текущего редактора. Несохранённые
изменения состава, отсутствующая база, отмена или физическое удаление не
превращаются в готовый источник. Архивирование сохраняет содержимое шаблона;
`template.delete` источником не разрешён.

Проверка: очередь **1270/1270**, focused **24/24**, critical
**901/901**, source check. API/MySQL **377/377**, 395,3 секунды:
`resume-command-source-api-1.txt`. BE `83083c5` только локально, обработчик
`a631516`. В API добавлены 32 случая ожидания отдельной команды, отмены,
изменения/удаления источника и повтора после перезапуска.

Базовый UI-набор **24/24**, 3,2 минуты, Chromium/mobile WebKit без повторов
и пропусков: `resume-command-source-ui-2.txt`. Дополнительный набор **84/84**,
9,6 минуты: `resume-command-source-ui-4.txt`, также без повторов и пропусков.
Итого **84 новых сценария + 24 регрессионных**, без пересечения между двумя
успешными прогонами: отдельные команды от открытого снимка, после правки,
архивирование ожидающей копии, потеря ответа и восстановление с теми же ID.

Журналы очереди/модулей/critical/source: `resume-command-source-transport-1.txt`,
`resume-command-source-unit-1.txt`, `resume-command-source-critical-1.txt`,
`resume-command-source-check-2.txt`. Исходный runtime не менялся между этими
проверками и заключительным UI; уточнялись только тестовые ожидания.

Первый UI-прогон: 2 успешных, 2 ошибки ожидания текста сетевого сбоя при
архивировании, 20 не запускались. Интерфейс сообщал «Не удалось удалить шаблон:
Failed to fetch»; тест ожидал текст для другого результата. Помощник теперь
проверяет сообщение формы об ошибке удаления. Runtime между прогонами не менялся.

Первый дополнительный UI-набор остановился после 8 успешных и 2 ошибочных
ожиданий номера ревизии (74 не запускались). Для правки публичного шаблона
существует сохранённая цепочка save → publication → unpublish, поэтому
сервер подтвердил ревизию 10, а тест ожидал 9. Диагностика исходного редактора
подтвердила revision 10 и финальную команду publication; ребёнок ожидал её UUID.
Уточнены только ожидания этого варианта в тестах; runtime остался прежним.

Это не закрывает порядок из отдельного пакета, личные зависимости, создание
цели внутри копирования, файлы, восстановление архивов и хранение/аудит.
Критерии перехода 2/12 и административные 0/10 остаются открытыми. Нативные
сбои Linux WebKit не исправлены этим изменением.
