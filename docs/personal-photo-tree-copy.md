# Независимая копия дерева с фотографиями

Проверенный локальный участок 2026-09-08 после FE `8c937b3`; API `45dcd06`.
Публикация отложена пользователем. `PERSONAL_PHOTO_TREE_COPY_ENABLED = false`,
`BIKE_PACKING_CAUSAL_PHOTO_TREE_COPY_ENABLED` не включён.

## Контракт и подготовка

Прежний `photos.mutate/action: copy-batch` принимает отдельно проверяемый
`copyTree`: полный выбранный исходный layout, полный target layout, root ID,
выбор с/без содержимого, место вставки и разрешённые метаданные изменения.
Для каталожной сумки без содержимого sourceLayout=null: источником остаётся
полная точная версия владельца. Для дерева с содержимым необходима выбранная
укладка и проверенный состав её ветки. Owner manifests уже содержат все поля,
числовые версии владельцев/фото и новые UUID; пустые вложенные сумки обязательны.

Небольшой чистый placement compiler одинаков в FE и API. Он проверяет полный
состав без циклов/пропущенных детей, места, порядок, количества и private/locked
границы, затем возвращает только новый target layout. У существующих вещей
сохраняются количества и packed; у новых копий packed не наследуется.
Копирование новых владельцев, фото и размещения выполняется в одной SQL
транзакции. Ошибка последнего фото откатывает всех владельцев и укладку.

Каталожный batch и дерево используют общий жизненный цикл
`createPersonalPhotoCopySetSession`: UUID/снимки до первого await и окна выбора,
SELECT-only сверка всех источников, одна fileless запись outbox до отображения,
повтор с теми же ID/body и сохранение полного черновика после ошибки.
Обычные формы и произвольный photo batch не получают разрешения на размещение.

Обычная кнопка дерева ожидает durable session перед показом успеха. Link/missing
сохраняет прежний независимый gate. Удаление до ACK использует полную v2-ссылку
на batch; для дерева дополнительно сверяется точный результат удаления из
укладок, запрещены новые перемещения под видом удаления.

## Проверка

- 469 transport, 59 operation, 895 critical, 74 source/service и source checks.
  В transport включены 11 новых тестов
  compiler/session: с/без содержимого, root/nested, frozen data, quota, выключенный
  writer, неправильные версии/места, pending deletion.
- API/MySQL: 147/147 без skips, 154,49 с (`tree-copy-mysql-6.log`), Node 24.19.0
  из установленного bundled runtime. Восемь новых сценариев: root/nested ×
  с/без содержимого × исполнение/отмена. Настоящие фото, все копии и размещение,
  rollback последнего файла, reverse deletion, lost ACK/restart, поздний replay.
- Прогоны 1 и 4 аварийно завершили Node 24.15.0 с 3221226505 ещё на прежних
  сценариях. Причина не установлена; эти прогоны не являются приёмкой.
- Прогоны 2/3: корневые копии прошли, два nested-сценария остановились при
  восстановлении (`unconfirmed-owner`). Unit воспроизвёл непринятие производного
  parentId в результате; проверка допускает только пустое либо точно выбранное
  размещение, запрещая другое. Это исправление ещё не решило весь nested путь.
  Прогон 5 завершился без native crash; все отмены и корневые копии прошли,
  nested deletion получил `invalid_photo_result_reference`. По сохранённым
  квитанциям отдельно воспроизведена причина: несъёмные вложенные контейнеры
  удаляются вместе с родителем, хотя явно выбран только родитель. Resolver
  теперь доказывает cascade по полной квитанции непосредственного предшественника
  с точной идентичностью и числовой версией. Общий structural helper обходит
  каждую укладку отдельно: связи из разных укладок не складываются в вымышленное
  дерево. Съёмные сумки и вещи остаются. Новые unit-проверки и обе сохранённые
  ошибочные квитанции проходят; итоговый API-прогон 6 полностью принят.
- UI: 32/32 Chromium/mobile WebKit без повторов, 6,8 минуты (`tree-copy-ui-4.log`).
  Включены 12 новых случаев (2 выбора состава × lost ACK/quota/cancel × 2 браузера)
  и прежние link/missing/no-photo сценарии.
- UI 1/2 обнаружил неполный старый формат целевой тестовой укладки. Исправлена
  фикстура независимой копии, strict baseline-проверка осталась, добавлен
  отрицательный unit-тест. UI 3 выявил, что отказ подготовки необязательной
  независимой копии блокировал link/missing. Теперь каждый вариант проверяется
  отдельно: неудача copy не разрешает copy и не запрещает допустимую связь.
  Это закреплено проверкой настоящей функции UI и полным повтором 4.
