# Размещение существующего дерева с фотографиями

Локальный участок 2026-09-08; публикация отложена пользователем.
`PERSONAL_PHOTO_TREE_LINK_ENABLED = false`.
Серверные сценарии зафиксированы локально в `57c0516`.

Общий `preparePersonalContainerTreeCopy` готовит варианты link/missing для
подтверждённых личных фотографий того же списка. Полный фотоинвентарь исходного
состояния проверяется до изменения состава; выбранные фотографии должны точно
совпадать с исходными владельцами. Незавершённые файлы, другой список, неполные
или изменённые ссылки, повторные публикации и повреждённые деревья блокируются.

Снимки, связи и количества фиксируются до первого ожидания и подтверждения.
Варианты link/missing не выделяют новые ID владельцев, не создают staging и
не копируют файлы. Количество берётся из выбранной исходной укладки, независимо
от количества в каталожной записи. Независимая копия дерева с фото пока требует
следующего атомарного адаптера: этот участок не выдаёт для неё результат copy.

Размещение сохраняется одной прежней причинной операцией list.update, которая
проходит полный guard неизменности фото. Серверные зависимости/CAS защищают
замороженное состояние; поздняя копия/удаление не обходят tombstones.

Проверено: 458 transport, 895 critical, 74 source/service, source checks.
139/139 API/MySQL, 95,35 с, без skips (`photo-tree-mysql-2.log`): настоящие
серверные фото вещи и сумки, link/missing, обратная доставка, потеря ACK,
restart, удаление источников, старые повторы и фото-tombstones.

Браузерная приёмка: **20/20 Chromium/mobile WebKit**, 4,5 минуты, без повторов
во втором прогоне (`photo-tree-ui-2.log`). Все процессы завершены.
Первый прогон прошёл 5 прежних сценариев и остановился при добавлении вложенной
вещи после размещения дерева с фото. Фото оставались неизменными; guard ошибочно
требовал уже удалённого исторического предшественника подтверждённого checkpoint.
Новый `outbox.confirmedBoundary()` возвращает только проверенную границу
журнала. Фото-preflight завершает обход на ней, сверяет полный исходный payload
и числовую revision каждого нового шага, а API receipt всё равно читается
обычной очередью. Регрессионный тест создаёт настоящий outbox, два checkpoint
с compaction и последующее изменение; подмена границы/версии/фото отклоняется.
Первый запуск MySQL-обвязки через PowerShell 5 завершился до тестов из-за
потери кавычек аргумента; лишний одноразовый listener проверен по @@datadir
и остановлен. Прямой запуск через текущий PowerShell 7 прошёл, MySQL остановлен.
