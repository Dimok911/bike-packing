# Большая операция при заполненном localStorage

В v1623 сохраняемое действие уже находилось в личной очереди, но транспорт
перед отправкой создавал ещё одну полную копию body в localStorage. При нехватке
квоты setItem завершался ошибкой `Cannot persist request journal; write was not sent`.
Отправки не было. Сценарий воспроизведён на сборке v1623 в mobile WebKit с большим
набором данных и отказом большой записи журнала: сервер получил 0 операций.
Состояние хранилища физического телефона непосредственно не измерялось.

Исправление в адаптере Bike Packing, не в переносимом ядре: тела list.update
больше 64 Ki кодовых единиц сохраняются в отдельной IndexedDB
`bike-packing-request-bodies-v1`. Маленький транспортный маркер остаётся в
localStorage. Один Web Lock удерживается до завершения транзакции, чтения
сохранённого тела, проверки SHA-256 и публикации/чтения маркера. До этого
бизнес-запрос не отправляется. Серверный формат и номер операции не меняются.

Очередь отдельно подготавливает журнал и читает тела при восстановлении.
Неизвестная или повреждённая ссылка блокирует сохранение; чтение сервера и
фотографий доступно. Запись ошибки и квитанции не возвращает большое тело в
localStorage. После долговечного подтверждения тело освобождается при следующей
подготовке очереди. Незавершённые тела сохраняются; тела без опубликованного
маркера освобождаются под тем же межвкладочным замком. Старые записи не удаляются
и продолжают читаться прежним способом.

Ограничение: личная очередь и маленькие маркеры пока остаются в localStorage.
Это убирает дополнительную полную копию при отправке; это не завершение перевода
всей очереди в асинхронное хранилище и не частичная загрузка укладок.

Проверки: отказ квоты и транзакции, потеря ответа, холодное восстановление,
подмена владельца/списка/отпечатка, отсутствующее тело, освобождение подтверждённой
и не отправленной записи. Браузерный сценарий меняет настоящую форму вещи,
сохраняет фотографии, использует реальную IndexedDB и проверяет один серверный
эффект после двух перезагрузок. Физический телефон проверяется после выпуска.
