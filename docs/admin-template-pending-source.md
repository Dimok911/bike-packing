# Копирование из ожидающего административного источника

Локальное продолжение перехода от 11.09.2026. Публикаций нет, общий
`ADMIN_TEMPLATE_OPERATIONS_ENABLED` остаётся OFF.

Административный `template.copy` и `template.save` с отдельным источником
принимают `source.base: { operationId }` вместо подтверждённой revision.
Источник остаётся привязан к точному namespace, администратору и хешу всего
снимка. Личный источник `kind: personal-list` по-прежнему принимает только
revision; обратный личный импорт также не расширялся этим срезом.

Сервер ищет предшественника в административном журнале того же аккаунта,
внутри прежней транзакции с блокировкой каталога. Неизвестное/ожидающее действие
даёт квитанцию `waiting` без изменения цели и отпускает блокировки. После
подтверждения используется именно revision его результата. Отмена или чужая
целевая запись в квитанции дают `template_source_dependency_rejected`.
Изменившийся после этого источник, неверный снимок или изменившаяся цель
отклоняются, а не подменяются актуальной версией. Повтор и отмена сохраняют UUID.

Отдельная capability `adminTemplatePendingSourceV1` не позволяет новому клиенту
отправить такой выбор старому серверу. После окончательного подтверждения его
чтение остаётся доступным без этой capability. Клиент принимает ожидание только
явно указанного предшественника.

Формы копирования вещи и сумки между demo/shared умеют читать ожидающий источник
из проверенного сохранённого плана. Поддержан один уже записанный шаг данных
`template.create`/`template.save`, в том числе source-checked save. Снимок
редактора обязан полностью совпасть с телом этого шага. Несохранённая поздняя
правка, смена источника/цели/аккаунта и отменённый план не принимаются.
Цель пока должна быть подтверждена. Копирование целого ожидающего шаблона через
форму также проверено следующим срезом: `admin-template-pending-whole-copy.md`,
UI 40/40 + 36/36 (48 новых сценариев и 28 регрессионных). Цепочки публикации,
ожидающие личные источники и файлы остаются открытыми.

Выбор источника, состав копии и новые ID сохраняются в прежнем целевом плане.
После перезагрузки источник продолжается своим сохранённым действием, затем
целевой шаблон — исходной копией. Пока источник не подтверждён, серверная цель
остаётся прежней; локальная копия отмечена как ожидающая.
